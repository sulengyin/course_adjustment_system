# 权限矩阵

> 规则：
> 1. 服务端逐操作、逐资源校验；前端隐藏入口不构成授权。
> 2. 角色之间**互不蕴含**：管理员不因技术权限获得业务权。
> 3. `TBD_BLOCKED` 表示该校方尚未指定责任人，**实现层必须拒绝**，并在界面显示"待校方确认"，不得临时授予任何人。
> 4. 一人多角色时必须显式 `actingAs`，否则拒绝（`AMBIGUOUS_ROLE`）。

## 角色

| 代号 | 角色 | 说明 |
|---|---|---|
| T | 教师 | 承担授课任务 |
| S | 课务管理人员 | 维护课表/校历/导入/发布 |
| C | 协调者 | 当前唯一承接协调责任的人（动态） |
| R | 记录者 | 授权登记口头/线下事实 |
| J | 争议裁决者 | **名单未定** |
| A | 系统管理员 | 开户、权限、备份、部署 |

## 关键说明

1. **管理员的三条禁令**：不得确认、不得裁决、不得代发起。管理员能做的只有开户、权限绑定、备份、部署。
2. **记录者（R）当前整体处于 `TBD_BLOCKED`**。R05 观察到代课由年级组长协调登记，但"年级组长"不是系统角色，不得自动映射（DIF-07）。在 D06/D07 关闭前，R 类操作全部拒绝。
3. **协调者（C）是动态角色**，不是固定岗位：由"先有效接单"产生，可移交，可因裁定而变更。
4. **发布（S 的第二项）标 `TBD_BLOCKED`**：V2.3 明确"指定部门/负责人正式发布"但岗位未证实。首版可导入、可比对、可预览，但**不能点"发布"**，直到学校指定人。
5. 上述 `TBD_BLOCKED` 的实现方式：接口返回 `403` + `code=ROLE_NOT_ASSIGNED`，界面显示"该职责待校方确认"，并记录尝试审计（用于发现越权尝试）。
