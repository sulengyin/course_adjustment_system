# 演示环境与正式环境的隔离（P7C）

## 1. 为什么必须分开

曾经这两个环境是混在一起的：同一个库里既有虚构教师与虚构课表，也有真实教师名单与真实账号。
问题不在于"数据多"，而在于**同一份数据会被当成两种东西**：

- 演示数据被当真：试功能时改掉的一条课次，看起来和真实课次没有区别；
- 真实数据被当假：演示库里的东西默认"可以随便试、随便删"，真实教师名单一旦进去，
  就处在"本该被保护、实际没人当回事"的状态。

所以隔离不是加个开关，而是让**一个库从建立时就固定属于一种环境**，并且两类数据彼此进不去。

---

## 2. 两种环境

| | 演示 / 联调（DEMO） | 正式业务（PRODUCTION） |
|---|---|---|
| 内容 | 全部虚构（`SIMULATED`） | 真实业务数据 |
| 允许 | 载入虚构种子数据 | 导入真实名单、真实课表、批量开号 |
| 禁止 | 导入真实名单、真实课表、真实花名册 | 载入虚构演示数据 |
| 用途 | 试功能、培训、演示 | 实际运行 |

环境写在库的 `meta` 表里（`deployment_mode`），**一经设定不可更改**。
想换环境只能另建库——否则此前所有数据的归属都要重新解释，谁也说不清哪条是真的。

---

## 3. 谁会拦住误操作

| 操作 | DEMO 库 | PRODUCTION 库 |
|---|---|---|
| `npm run seed-demo` | 允许（空库自动标为 DEMO） | **拒绝** |
| `npm run import-teachers` | **拒绝** | 允许 |
| `npm run bulk-users` | **拒绝** | 允许 |
| `npm run serve` | 允许 | 允许 |
| 库未设定环境 | **拒绝启动**：界面无法标明，用户会把演示数据看一轮 | 同左 |

`npm run set-mode` 本身也有两道闸：

- 库里已有真实数据 → 不能标为 DEMO；
- 库里仍有虚构数据 → 不能标为 PRODUCTION，除非显式加 `CA_PURGE_SIMULATED=1`，
  且库里**没有任何已生效业务事实**（调课方案、生效记录、求助、导入批次）才允许清除。

清除虚构数据时，绑定虚构教师的账号**停用而不是删除**：账号存在过这个事实要留在审计里。

---

## 4. 怎么用

```bash
# 建一个演示库（自动标为 DEMO）
CA_DB_PATH=<演示库路径> npm run seed-demo

# 建一个正式库（空库起手最干净）
CA_DB_PATH=<正式库路径> CA_MODE=production npm run set-mode
CA_DB_PATH=<正式库路径> CA_ACTOR_LOGIN=<课务账号> CA_ACTOR_PASSWORD=<口令> \
  CA_ROSTER_CSV=<名单> npm run import-teachers
```

既有演示库要转成正式库：

```bash
CA_DB_PATH=<库路径> CA_MODE=production CA_PURGE_SIMULATED=1 npm run set-mode
```

## 5. 界面上的标识

页面顶部有一条**常驻横幅**，登录前就显示：

- 演示环境：「演示 / 联调环境　库内全部为虚构数据　不得导入真实名单与真实课表」
- 正式环境：「正式业务环境　库内为真实业务数据　不得载入虚构演示数据」

横幅数据来自 `/api/env`（免鉴权，只返回一个环境标识，不含业务数据）。
拿不到就保持隐藏——不猜，不默认当作某一种环境。

备份的 `manifest.json` 也记录 `deploymentMode`；
把演示备份恢复成正式库，后果与备份损坏同级，所以恢复前要看得出来。

---

## 6. 两个环境不要共用口令

正式库的管理员口令**不得**与演示库相同，尤其不得沿用种子脚本的默认值
（该默认值写在公开仓库里，任何人都看得到）。首次正式使用前必须改掉。

教师账号的初始口令由系统逐个生成，清单保存在仓库之外，分发后删除本地副本。

---

## 7. 已知缺口

- **真实校历（学期）导入尚未实现**：正式库目前没有学期，因此在导入真实课表之前，
  课表页是空的。要装真实课表，还需要依次补：真实校历、班级名单、科目名单、课表导入。
- 管理员重置他人口令尚未实现，而正式环境下"教师忘记口令"只能靠管理员重置。
