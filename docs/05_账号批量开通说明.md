# 账号批量开通说明

- 状态：**本文件是本项目提出的操作方式，不是学校已确认的制度**。校方如有现成花名册格式，以此为准调整列名。
- 覆盖：为已存在的教师批量开通登录账号。
- 不覆盖：课表导入（见 `docs/04`）、课后服务与安排表（系统暂无对应模型）。

---

## 1. 前置条件（很容易被忽略）

**教师档案必须已经存在。** 批量开通只建登录账号，不建教师档案；花名册里的"教师编号"如果在系统里查不到，整批会被拒绝（避免造出指向空档案的孤儿账号）。

当前教师档案只有两个来源：

| 来源 | 状态 |
|---|---|
| 课表导入 | 代码能力已有，但**尚无 CLI / 页面入口**（见 §5 未完成项） |
| 演示种子 `seed-demo` | 仅有虚构教师 T01–T03 |

也就是说：**在教师名单导入做好之前，批量开通用不了真实数据**。这是已知的缺口，不是遗漏说明。

## 2. 花名册 CSV 格式

四列，**列名必须完全一致**（不做别名猜测，缺列直接报错）：

| 列名 | 必填 | 说明 |
|---|---|---|
| 账号 | 是 | 3–32 位小写字母、数字、点、下划线、连字符，以字母或数字开头 |
| 姓名 | 是 | 显示名 |
| 教师编号 | 教师角色必填 | 必须已存在于教师档案；**非教师账号必须留空** |
| 角色 | 是 | `T` 教师 / `S` 课务管理人员 / `A` 系统管理员；多个用 `+` 连接，如 `T+S` |

示例：

```csv
账号,姓名,教师编号,角色
teacher01,示例教师甲,T01,T
teacher02,示例教师乙,T02,T+S
staff01,课务管理员,,S
```

- 编码 UTF-8（可带 BOM）；GBK 会在解析阶段明确报错。
- 文件扩展名 `.csv`。列数不齐直接报错，不补齐、不跳过。

## 3. 整批拒绝规则

**任何一行有问题，一个账号都不建。** 审计链不可回滚，建到一半留下的半批账号比整批拒绝更难交代。

| 情况 | 提示 |
|---|---|
| 账号为空 / 格式不符 | `BAD_INPUT` |
| 姓名为空 | `BAD_INPUT` |
| 同一份花名册里账号重复 | `DUPLICATE_IN_FILE` |
| 账号在系统中已存在 | `LOGIN_NAME_TAKEN` |
| 教师档案里没有该编号 | `TEACHER_NOT_FOUND` |
| 同一教师编号在花名册里给了两个账号 | `DUPLICATE_TEACHER_IN_FILE` |
| 教师编号已绑定其他在用的账号 | `TEACHER_ALREADY_BOUND` |
| 教师角色未填教师编号 | `BAD_INPUT` |
| 非教师角色填了教师编号 | `BAD_INPUT`（提示写作 `T+S`） |
| 角色未填写 / 未知角色 | `BAD_INPUT` / `UNKNOWN_ROLE` |
| 角色含 C / R / J | `ROLE_NOT_GRANTABLE`（这些职责须由校方指定承接人，系统不得代授） |

一份教师档案只挂一个在用的账号。两个账号共用同一编号，会让"这节课到底归谁"在调课与确认时说不清。

## 4. 执行方式

```bash
CA_DB_PATH=/data/ca.sqlite \
CA_ADMIN_LOGIN=admin \
CA_ADMIN_PASSWORD='执行人口令' \
CA_USERS_CSV=/data/花名册.csv \
CA_OUT_FILE=/data/口令清单.txt \
npm run bulk-users
```

- `CA_ADMIN_PASSWORD` 仅用于本次登录确认操作人身份，不落盘、不入日志。
- 执行人必须具 `MANAGE_ACCOUNTS` 权限，且自己已完成首登改密。
- `CA_OUT_FILE` 可选；写出时权限为 `0600`。
- 退出码：`0` 成功；`1` 解析/预检/建号失败；`2` 缺必填环境变量。

## 5. 口令策略（为什么没有"统一口令"）

- 初始口令由系统生成：**12 位以上，字母+数字各至少一位，每人不同**。
- 建号后 `must_change_password = 1`，首次登录必须修改，未改密前不能使用任何功能。
- **不接受外部指定统一口令**（例如 `t123456`）：长度不足会被口令强度拒绝；即便放行也会被首登强制改密冲掉；且同一口令意味着任何人知道即可登录全部账号，审计里无法区分操作人。

建议：把清单逐行剪开分发给本人，分发后立即删除本地副本。系统不采集手机号，无法自助找回，忘记口令只能由管理员重置（见 `docs/08`）。
