# 规则分层与配置化设计

- 版本：R0 / 2026-10-31
- 依据：项目负责人 2026-10-31 指示（"部分待确定规则放入设置项，由后期使用者勾选；区分通用默认规则与可调整规则"）+ V2.3 / R05 既有约束
- 性质：设计约定，**不是**学校已批准的制度
- 关联：`00_项目接手审查报告.md` §5（未决清单）、`01_分阶段计划与P1执行计划.md`

---

## 1. 一句话结论

**参数可以配置，制度不能勾选。**

凡是"换一个值只会改变时间、格式、范围"的，做成设置项，且**不提供默认值**；
凡是"换一个值会改变谁有权力、谁算同意、什么算生效"的，**不得做成开关**，只能做成"待校方确认的能力"，默认关闭、开启须登记书面依据。

原因：设置页的第一个使用者往往是系统管理员。若把"沉默是否算同意""调课单是否等于本人确认"做成复选框，等于让管理员单方面决定学校制度，直接违反 V2.3 A5/A6 与 R05 D04（"不授予管理员默认裁决权"）。

---

## 2. 判定方法（一句话测试）

> 把这个值从 A 改成 B，会不会改变**"谁有权 / 谁算同意 / 什么算生效 / 什么算已完成"**？
>
> - **会** → 不是设置项（L0 硬不变量，或 L2 待决制度）
> - **不会，只改变时间点、阈值、格式、范围** → 设置项（L1 校本参数）

举例：

| 候选 | 测试结果 | 归类 |
|---|---|---|
| 第 4 节 11:20 还是 11:25 | 只改时间 | L1 |
| 补确认截止是 17:00 还是 24:00 | 只改时间点 | L1（但"必须在下一个工作日结束前"本身是 L0） |
| 升级阈值 3 分钟还是 10 分钟 | 只改时间点 | L1 |
| 课后服务算硬冲突还是仅提醒 | 改的是"什么会挡住生效" | L2 |
| 口头登记能否替代本人确认 | 改的是"谁算同意" | L0 禁止 + L2 待决 |
| 调课单张贴是否等于双方同意 | 改的是"谁算同意" | L2（D01/D02） |
| 管理员能否直接改课表 | 改的是"谁有权" | L0 禁止 |
| 界面用不用深色模式 | 只改显示 | 个人偏好 |

## 3. 三级分层

### L0｜硬不变量：不可配置、不可关闭、不可用开关绕过

来自 V2.3 CONFIRMED / R05 CONFIRMED。写进代码作为断言，任何 L1/L2 配置都不能使其失效。

| ID | 不变量 |
|---|---|
| INV-01 | 沉默 / 已读 / 未回复 / 过期 ≠ 同意 |
| INV-02 | 登记临时安排 ≠ 教师接受 ≠ 正式生效 ≠ 已执行 |
| INV-03 | 口头登记 ≠ 本人电子确认；补确认不倒填时间 |
| INV-04 | 协调结案 ≠ 授课事实已核验 ≠ 课程已完成 |
| INV-05 | 导入文件 ≠ 学校正式发布 |
| INV-06 | 已执行授课事实不可被恢复方案改写 |
| INV-07 | 必要确认者由受影响集合计算，不由发起人指定 |
| INV-08 | 系统管理员不代确认、不默认裁决、不因技术权限获得业务权 |
| INV-09 | 生效后不可删除，取消须新建方案并重新确认 |
| INV-10 | 纯资料纠错不得改变实际授课/工作责任 |
| INV-11 | 无占用记录 ≠ 有空；有空 ≠ 愿意 |
| INV-12 | 服务端逐操作、逐资源校验；前端隐藏不算授权 |
| INV-13 | 第一版纯校内访问，校外不得直连 |
| INV-14 | 任何变更不得静默覆盖已生效事实 |

> 设置页**不得出现**上述任一项的开关。代码评审时以此表为准。

### L1｜校本参数：可配置，**无默认值**

特点：值属于"学校本地事实"，必须由学校填；系统**不猜**。

- 未配置时：依赖该参数的能力返回 `NOT_CONFIGURED`，界面显示"待配置"，**不得**回退到任何内置数值
- 配置需：填写人、时间、依据（可为"学校提供"）、生效范围（学期）
- 变更审计、可回滚、可导出快照

| 键 | 含义 | 未配置时的行为 | 权威方 |
|---|---|---|---|
| `school.name` / `school.termLabel` | 校名、学期显示 | 显示"未配置" | 课务管理人员 |
| `school.timezone` | 时区 | 阻断所有时间计算 | 部署方 |
| `calendar.term` | 学期起止、上课日 | 无法生成课次 | 课务管理人员 |
| `calendar.exceptions` | 节假日、调休、考试周、活动日 | 按"无例外"处理并显式标注 `NO_EXCEPTION_CONFIGURED` | 课务管理人员 |
| `bell.schedule` | 节次表（第几节、起止） | 无法生成课次 | 课务管理人员 |
| `rotation.parityBase` | 单双周基准周 | 单双周课次返回 `NOT_CONFIGURED` | 课务管理人员 |
| `makeup.deadlineClock` | "下一个工作日结束"的钟点 | 逾期判定为 `NOT_CONFIGURED`，不判逾期 | 校方（BIZ-04） |
| `escalation.thresholds` | 升级阈值/等级 | 仅支持人工升级，不自动升级 | 校方（时间参数） |
| `escalation.reminders` | 首次/重复提醒间隔 | 不发自动提醒 | 校方 |
| `conflict.severity[type]` | 每类占用（课后服务/值班/教研/早读/午间/校外活动）的硬/软级别 | 该类型记为 `UNKNOWN`，校验结果标"未校验项 N 个"，**不得**当作无冲突 | 校方（BIZ-08） |
| `import.strictness` | 导入容差（表头别名、日期格式、空行） | 安全默认 = 严格（可放严不可放宽） | 课务管理人员 |
| `import.unsupportedFormats` | 不支持的格式清单 | `.docx` 明确 `UNSUPPORTED_FORMAT` | 开发方 |
| `retention.days` | 数据留存期限 | 显示"未设定"，不自动删除 | 校方（BIZ-10） |
| `backup.rpo` / `backup.rto` | 备份目标 | 显示"未设定" | 校方 |
| `session.idleTimeout` | 会话超时 | 允许安全基线默认（标注"技术基线，非学校制度"） | 部署方 |
| `notification.channels` | 系统内待办开关；钉钉/短信位为空 | 仅系统内待办 | 校方（T01 未定前不得启用外渠道） |
| `print.template` | 调课单/代课单模板、抬头 | 使用无抬头通用版并标"非学校正式单据" | 校方（BIZ-12） |

> **L1 的铁律：不提供"推荐值"按钮，不预填示例数字。** 空格就是空格。

### L2｜待决制度：默认关闭，开启须登记依据

特点：对应 V2.3 / R05 中"学校待决"的事项。系统只承载学校的决定，不替它决定。

- 默认状态：`DISABLED`
- 关闭时：相关能力不可用，返回 `FEATURE_NOT_ENABLED`，界面文案统一为"该规则待校方确认，暂不可用"，**不得**显示"暂按 X 处理"
- 开启需同时具备：依据文件编号 / 依据类型（制度、会议纪要、书面批复）/ 批准人 / 生效日期 / 适用范围（学期或全校）
- 开启动作本身写入审计，并生成"制度变更记录"，可追溯到"谁声称学校已决定"
- **即使开启，L0 不变量仍然有效**

| 键 | 对应未决 | 开启后系统才允许的行为 |
|---|---|---|
| `policy.offlineNote.acceptAsConfirmation` | D01、D02 | 把线下调课单/口头同意作为"每名教师本人确认"的可接受证据 |
| `policy.scheduleVersion.conflictMode` | D03 | 新版课表与既有有效变更重叠时的处理策略 |
| `policy.dispute.adjudication` | D04 | 指定争议裁决角色与流程 |
| `policy.occupancy.shareScope` | D05 | 强制共享某类动态占用 |
| `policy.correction.whitelist` | BIZ-01 | 允许免确认纠正的字段白名单 |
| `policy.coordination.autoAssign` | O2-1、D07 | 口头/在线接单冲突的自动裁定 |
| `policy.coordination.autoEscalate` | O4-1、时间参数 | 依阈值自动升级 |
| `policy.makeup.lateAllowed` | BIZ-04 | 逾期后仍允许补确认 |
| `policy.rotation.computeRule` | BIZ-06 | 轮换课按日历奇偶/实际次数推算 |
| `policy.afterSchool.filing` | BIZ-07 | 备案课后服务作为硬冲突依据 |
| `policy.execution.completionCriteria` | BIZ-03 | 判定"已执行"的依据 |
| `policy.settlement.stateFlow` | D08 | 代课记录推进到"可结算"（**仍不产生金额**） |
| `integration.dingtalk` | T01 | 钉钉容器/免登（需校方授权，不得预先建设） |

> 说明：`policy.settlement.stateFlow` 即使开启，也**只允许状态流转，不允许金额、补贴标准、发放动作**。R05 已明确"一节 10 元"不是规则。

## 4. 配置治理规则

1. **无默认值**：L1 不预填；L2 默认关。
2. **无"推荐配置"**：不提供一键套用模板，避免把开发方的猜测固化成学校制度。
3. **依据必填**：L2 无依据不可开启；L1 允许"学校提供"作为依据类型。
4. **版本化**：每次变更生成 `config_revision`，含变更前后值、操作者、时间、原因。
5. **可预约生效**：学期中切换须指定生效时点，避免半途改变判定口径。
6. **影响提示**：变更前提示受影响对象数（如"将影响 12 个进行中的方案"）。
7. **可回滚**：保留上一版本，支持整体回退。
8. **可导出**：配置快照可导出/导入，用于部署迁移与审计取证。
9. **三项分离**：
   - 学校级策略（L1/L2）—— 仅校方授权角色可改
   - 个人偏好（通知方式、默认视图、字号）—— 教师本人可改，**不得影响任何业务判定**
   - 会话级筛选（班级、周次）—— 临时，不持久化为规则
10. **个人偏好禁止项**：不得出现"允许他人代我确认""自动同意调课""默认我有空"这类选项。此类选项一旦存在，等价于系统内置"沉默即同意"。

## 5. 未配置时的系统行为（必须显式，不得降级）

| 情形 | 正确行为 | 禁止行为 |
|---|---|---|
| 节次表未配置 | 返回 `NOT_CONFIGURED`，页面提示"请先配置作息" | 使用内置 40 分钟课时 |
| 冲突级别未配置 | 校验结果含 `UNCHECKED` 项并计数 | 视为"无冲突"通过 |
| 升级阈值未配置 | 只能人工升级 | 用 5 分钟兜底 |
| 留存期限未配置 | 不自动清理 | 用 180 天兜底 |
| L2 未开启 | `FEATURE_NOT_ENABLED` | 用"暂按宽松处理"放行 |

**统一措辞**：`待配置` / `待校方确认` / `未校验`。禁用"暂定""默认按…""一般情况"。

## 6. 模拟数据策略（全流程）

在你提供真实作息表、班级课表、教师课表、课后服务安排表、每周工作表之前，**全部功能测试只使用模拟数据**。为防止模拟数据被误当真实数据，落实以下约束：

### 6.1 数据来源标记

每条业务数据带 `data_origin`：

| 值 | 含义 | 允许的操作 |
|---|---|---|
| `SIMULATED` | 虚构 | 可查询、可推演；**不可**标记为正式发布；导出带水印 |
| `IMPORTED_UNVERIFIED` | 导入未核验 | 可预览、可校验；不可作为正式基准 |
| `OFFICIAL` | 学校确认发布 | 全功能 |

### 6.2 隔离要求

1. 系统运行模式 `SIMULATION` / `PRODUCTION` 二选一；`SIMULATION` 下全局常驻横幅"演示数据，非学校真实课务"。
2. 模拟数据**一键清空**（只删 `SIMULATED`，不触碰其他来源）。
3. 真实数据导入前强制检查：若存在 `SIMULATED` 残留，必须显式确认清除，禁止混合。
4. 导出文件（Excel/PDF/打印）自动带 `SIMULATED` 标识；不得输出可被误认为学校正式单据的文件。
5. 模拟数据不得进入备份恢复演练之外的任何"正式"流程。

### 6.3 模拟数据集设计

需覆盖 AC01–AC14，且**故意包含矛盾样本**（否则测不出拒绝能力）：

- 虚构学校 1 所、虚构教师 40 人（含同名不同 ID 2 组、离职 1 人）、虚构班级 12 个、虚构学期 1 个
- 课表包含：单双周课、轮换课（用于验证 `UNKNOWN_ROTATION`）、连堂课、跨班任教
- 校历包含：节假日、调休、考试周、临时活动日
- 占用包含：课后服务（备案与实际不一致）、值班、教研、缺结束时间的校外活动
- 协同场景：三人互换、一人拒绝、一人沉默、方案版本中途变更、并发互斥、已执行课次混合
- 异常样本：错误日期、重复行、乱序行、非法教师 ID、缺少表头

### 6.4 措辞纪律

模拟数据全部通过，**只能**表述为"虚构样本通过"，不得写"支持学校真实课表"。S01 在真实样本核验前始终为 `OPEN`。

## 8. 与"通用默认规则 / 可调整规则"的对应

| 你的表述 | 本设计对应 |
|---|---|
| 通用默认规则 | L0 硬不变量（不可改）+ L1 的"安全默认"仅限技术基线（如导入严格模式、会话超时） |
| 可调整规则 | L1 校本参数（无默认值，由学校填） |
| 待确认规则 | L2 待决制度（默认关，开启须书面依据） |

差异点需你注意：**L1 不做"默认值 + 可改"，而是"空值 + 必填"**。因为一旦预填，使用者会直接沿用，等于开发方替学校定了作息和阈值。
