# 课表导入格式说明（P3，待校方确认）

- 状态：**本文件是本项目提出的导入格式提案，不是学校已确认的制度**。校方确认或提供样表后，以此为准修改。
- 当前支持：`.csv`（UTF-8）、`.xlsx`（第一个工作表）
- 明确不支持：`.docx`、`.doc`、`.xls`、`.pdf`、图片

---

## 1. 必需的列

| 列名 | 含义 | 允许的写法 | 示例 |
|---|---|---|---|
| 教师 | 任课教师 | 教师姓名或教师工号 | 示例教师甲 / T01 |
| 班级 | 授课班级 | 班级名称或班级编号 | 虚构一年一班 / C1 |
| 科目 | 学科 | 科目名称 | 语文 |
| 星期 | 每周几上课 | `1`–`5`、`周一`–`周五`、`星期一`–`星期五`、`MON`–`FRI` | 周一 |
| 节次 | 第几节 | 数字，或 `第3节` | 2 |

## 2. 可选的列

| 列名 | 含义 | 缺省处理 |
|---|---|---|
| 单双周 | 该课是每周 / 单周 / 双周 | 留空 = 每周（`ALL`） |
| 生效起 | 从哪天起生效 | 留空 = 整个学期 |
| 生效止 | 到哪天止生效 | 留空 = 整个学期 |

单双周可写：`每周` / `单周` / `双周`，也接受 `ALL` / `ODD` / `EVEN`。

## 3. 表头别名

系统会识别常见别名，例如"任课教师""授课教师""教师姓名"都会映射到"教师"。**识别结果只是建议，必须由操作人确认后才生效**；不会按列的位置猜测。

## 4. 整批拒绝的规则

出现以下任一情况，整个文件被拒绝，一条数据都不会写入：

| 情况 | 说明 |
|---|---|
| 表头缺列 | 教师/班级/科目/星期/节次缺任意一列 |
| 未知教师 / 未知班级 / 未知科目 | 名称在系统里找不到 |
| 同名无法区分 | 例如两位教师都叫"张老师"，必须改用工号 |
| 日期格式错误 | 生效起/止不是 `YYYY-MM-DD` |
| 生效止早于生效起 | — |
| 行内重复 | 同一份文件里出现两条完全相同的行 |
| 同一教师同一时段排两个班 | 结构性冲突 |
| 同一班级同一时段排两位教师 | 结构性冲突 |

例外：单周课与双周课占用同一时段**不算冲突**。

## 5. 列数不一致

某行列数与表头不一致时直接报错，不补齐、不跳过。宁可让人改文件，也不让系统猜。

## 6. 编码

CSV 必须是 UTF-8（带不带 BOM 都可以）。GBK 编码会明确报错，不会用替换字符硬解。

## 7. 与"发布"的关系

上传成功 ≠ 课表生效。上传后状态为 `IMPORTED_NOT_PUBLISHED`，必须由具备发布权限的人执行"发布"，课表才成为学校正式课表。发布动作会记录操作人与时间。

## 8. 待校方确认的问题

1. 学校现有课表是"周课表"（星期+节次）还是"日课表"（具体日期）？本格式按周课表设计。
2. 单双周的起始周由谁提供、写在哪里？
3. 一位教师跨年级任课是否有统一工号？
4. 是否存在同一个班同一时段两位教师（如主讲+助教）？若有，需要扩展为"多教师"模型而非冲突。
