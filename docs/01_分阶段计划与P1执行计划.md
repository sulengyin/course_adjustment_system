## 2. 全景计划与验收标准

### P1 契约与业务不变量（本阶段，详见 §3）

- **目标**：把 R05 AC01–AC14 与 V2.3 必测场景 1–15 转成**可执行、可失败**的规范，形成后续所有阶段的验收基线；同时把"可配置/不可配置"的边界固化为契约。
- **不产出**：任何生产业务逻辑、数据表、界面。
- **验收**：见 §3.3。

### P2 领域内核 + 只读课表

- **范围**：教师/班级/学科/任课关系/节次/学期/校历/课次生成（模板 + 例外 + 单双周）；教师视角与班级视角一致性；`UNKNOWN` 表达。
- **不含**：轮换推算（只 `UNKNOWN_ROTATION`）、任何写操作。
- **验收**：
  1. 虚构校历下，同一课次在教师视图与班级视图中 `teacher_id/class_id/time` 完全一致（属性测试 1000 组随机）。
  2. 缺结束时间的占用不产生 `ends_at`，查询返回 `certainty=UNKNOWN`，且不参与硬冲突。
  3. 单双周 + 调休 + 节假日边界用例全通过（含跨学期、考试周）。
  4. 轮换课次查询返回 `UNKNOWN_ROTATION` 且**无任何**推算值。
  5. 无 DB 迁移即可跑通（内存/临时库），所有数据为虚构。
- **门禁**：无

### P3 导入管线（虚构样本）

- **范围**：上传 → 类型/大小/内容校验 → 字段映射 → 校验报告 → 差异预览 → 确认提交 → 批次/来源/版本 → 幂等 → 撤销。解析器为可插拔接口，首版仅 CSV/XLSX。
- **不含**：Word、OCR、真实校方文件、"自动发布"。
- **验收**：
  1. 同一文件重复上传：`import_batch` 新增但 `lesson_occurrence` 净变化为 0（幂等断言）。
  2. 行顺序随机打乱后差异报告为"无变化"。
  3. 含非法行的文件：整批拒绝，正式数据哈希不变（AC08 前置）。
  4. 上传成功但未"确认正式发布"时，系统状态为 `IMPORTED_NOT_PUBLISHED`，课表查询不宣称"学校正式生效"（AC01）。
  5. 撤销批次后，已生效变更**不被删除**，只产生冲突标记（AC08）。
  6. 解析器接口对 ".docx" 明确返回 `UNSUPPORTED_FORMAT`，不得静默失败。
  7. 所有导入数据 `data_origin=IMPORTED_UNVERIFIED`，不得直接置为 `OFFICIAL`；存在 `SIMULATED` 残留时导入被拒绝并要求显式清除（CFG-08）。
- **门禁**：S01（真实格式）未关闭 → 不得对外宣称"支持学校课表"。

### P4 变更协商（线上本人确认闭环）

- **范围**：草案 → 受影响集合计算 → 逐人确认/拒绝/改案 → 版本绑定 → 冲突复核 → 单事务生效 → 审计 → 撤回（生效前）/恢复方案（生效后）。
- **不含**：线下调课单认定、口头代录、争议裁决、自动推荐。
- **验收**（全部虚构数据）：
  1. 必要确认者由受影响集合计算：三人互换场景中，班主任不出现在集合内但收到通知事件（R01）。
  2. 任一人拒绝 / 沉默 / 确认后方案版本变更 → 不生效（AC06）。
  3. 并发两个互斥方案：仅一个生效，另一个 409；审计与课表同事务（FR-10）。
  4. 同一请求重复提交（同幂等键）只产生一次变更。
  5. 生效后"删除"接口返回 405/不存在；取消必须走恢复方案且重新确认（R02）。
  6. 含已执行课次的方案，恢复只作用于未执行部分（R02-A）。
  7. 改变责任的"纠错"被拒绝，返回 `REQUIRES_NEW_PROPOSAL`；纯资料纠错留前后值（D8 白名单未定 → 仅实现"一律拒绝"的安全默认？**否**——见下）。
- **注意（重要）**：纠错白名单未定（BIZ-01）。P4 **只实现** "识别到责任变化 → 拒绝并提示走新方案"这一确定方向；对"是否属于纯资料纠错"不做自动判定，统一返回 `TBD_CORRECTION_SCOPE`。宁可少做，不可错放。
- **门禁**：D01/D02 未关闭 → 不得接受线下材料作为确认输入。

### P5 部署与网络边界

- **范围**：校内机器部署包、内网绑定、TLS、备份恢复脚本、日志脱敏。
- **验收**：
  1. 从干净机器按文档部署成功（记录 OS/CPU/依赖来源）。
  2. 服务仅监听指定内网地址；`0.0.0.0` 绑定被配置校验拒绝。
  3. 校外移动数据访问 → 连接失败（记录设备/网络/时间/结果，AC12）。
  4. 独立环境恢复演练，对账：教师数、课次数、确认数、审计链、来源批次（AC14 支撑）。
  5. 日志检索：无教师请假原因、无手机号、无明文密码。
- **门禁**：T-01/T-02/T-03/T-06 未实测 → 不得写"部署就绪"。

### P6 应急协调（受限）

- **范围**：求助、临时登记、口头接受登记、补确认、责任组/主责/代理/兜底、结案提交与确认分离。
- **强制门禁**：D04、D06、D07、O2-1、O4-1、O4-2、O5、时间参数、BIZ-04、BIZ-05 中**影响已实现行为者**必须先关闭。未关闭时**只实现显式待核验状态与隔离测试**（R05 §5 Phase 2 明确允许）。
- **验收**：E1–E11 每条一用例，核心断言是"五件事互不蕴含"。
- **门禁**：任一必填项缺失 → 整个 P6 NO-GO。

### P7 真实格式与规模/兼容

- **验收**：脱敏真实课表导入核对报告（差异逐行可解释）；鸿蒙 PC/Windows/macOS Safari/鸿蒙手机/Android/iOS 实机主路径录像；200 人负载报告（含硬件、p95、失败率）；若未实测 → `NOT_RUN`。
- **每周工作计划**：仅做"来源位置 + 确定性"记录与人工确认，**不做**自然语言语义自动提取（属 V2.3 P2，需先证明价值）。"周三 13:00 外出"这类信息只记录已知部分，不推断结束时间、不自动全天阻断。
- **门禁**：S01 + T-04 + T-08。

### P8 规则收口与上线门禁

- **验收**：D01–D08 全部有校方书面依据；权限矩阵无 `TBD_BLOCKED`；回滚演练；培训材料；退出/数据导出方案。
- **门禁**：任一 OPEN 项仍影响生产行为 → NO-GO。

### 3.5 技术选择（临时，可替换）

P1 只用**纯函数 + 数据夹具**，不涉及框架、数据库、网络：

- Node 24 + TypeScript + Vitest（本机已具备；无框架锁定风险）
- 目录：`spec/`（契约与用例）、`docs/`
- 不引入任何运行时依赖，确保可在**无外网**环境重跑（T-06 预演）

若你倾向 Python 或希望此时就定后端栈，请在审阅时指明，我按你的选择重做 S6–S9（其余交付物与语言无关）。

**此阶段不选型**：不决定数据库、Web 框架、部署形态、是否容器。这些都是 P2 起才需要、且受 T-02 约束的事。

## 5. 交接承诺

每阶段结束提交的报告固定包含（R05 §8）：

1. 已读取资料的版本与哈希
2. 本阶段允许实现的范围、拒绝猜测的事项
3. 设计取舍与对应需求 ID
4. 改动文件、运行命令、测试结果、未通过场景
5. 引入的假设、风险、对后续的影响
6. 下一阶段进入条件

判定用语严格：未运行写 `NOT_RUN`，失败写 `FAILED`，部分通过不得写"通过"。
