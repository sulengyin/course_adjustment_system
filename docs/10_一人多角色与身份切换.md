# 一人多角色与身份切换（P7F）

- 适用范围：同一账号承担多重职责（例如既管开户、又管课务资料导入）。
- 不适用范围：**不提供"超级管理员"**。角色互不蕴含，授权只增加可切换的身份，不合并权限。

---

## 1. 为什么不做「一键全权限」

系统一开始就把"管理员不得确认他人课务、不得裁决、不得代发起"写成硬约束（`docs/permission-matrix.md` §关键说明 1，追溯表 INV-08）。理由不是保守，而是审计要能回答"这件事是谁做的"：

| 做法 | 审计里的 `actor` | 事后能否分清谁做的 |
|---|---|---|
| 一个账号拥有全部权限 | 永远同一个 ID | 不能 |
| 一人多角色 + 显式身份 | 同一个 ID + 不同的 `actingRole` | 能 |

当所有动作都来自同一个"超级账号"时，`LOGIN_SUCCEEDED` 之后的一切行为都失去区分力：导入错了数据、错停了账号、代谁发起了调课，都只能看到同一个操作者。

更实际的一条：**调课在数据模型上认教师档案**（`src/service/change-service.ts:227`）。`admin` 没有 `teacherId`，结构上就发起不了；要"代发起"必须新增 `onBehalfOf` 字段与对应权限，那是重做半条流程，不是勾一个选项。

## 2. 追加角色的正确做法

```bash
CA_DB_PATH=/data/.../school.sqlite \
CA_ACTOR_LOGIN=admin \
CA_ACTOR_PASSWORD='管理员口令' \
CA_TARGET_LOGIN=admin \
CA_ROLE=S \
CA_REASON='该校仅一名管理员，需同一账号兼顾开户与课务资料导入' \
npm run grant-role
```

| 变量 | 必填 | 说明 |
|---|---|---|
| `CA_DB_PATH` | 是 | 库必须已设定环境（DEMO / PRODUCTION） |
| `CA_ACTOR_LOGIN` / `CA_ACTOR_PASSWORD` | 是 | 执行人须具 `MANAGE_ACCOUNTS`（管理员 A），且已改密 |
| `CA_TARGET_LOGIN` | 是 | 被授权账号 |
| `CA_ROLE` | 是 | `T` / `S` / `A`；`C` / `R` / `J` 仍不可授予 |
| `CA_REASON` | 否 | 写入审计的理由（建议填） |

拒绝的情形：库未设定环境、执行人未改密、目标账号不存在或已停用、重复授予同一角色、授予 `C/R/J`、给无教师档案的账号授予 `T`。

授权写 `GRANT_ROLE` 审计，记 `objectId=被授权账号`、`afterState=角色`。

## 3. 登录与切换

**登录时**：账号有多个角色，必须显式指定本次身份（`actingRole`）。不指定返回 `409 AMBIGUOUS_ROLE`，并在响应里带回可选角色列表；网页上会展开"以哪个身份登录"下拉。

**登录后**：网页顶栏出现身份下拉，切换即调用 `POST /api/auth/switch-role`：

```json
{ "actingRole": "S" }
```

成功返回新令牌与新的 `principal`；**旧令牌当场作废**（会话记录 `revoked_reason = ROLE_SWITCH`），审计写 `SWITCH_ROLE`（`beforeState=A`、`afterState=S`）。

前端必须立刻替换本地 token——服务端已经吊销旧会话，继续用旧 token 会得到 `401 UNAUTHENTICATED`。

## 4. 边界：切了身份也不越权

授权是"多一个可用的身份"，不是"多一份权力"。以正式库的 `admin`（A+S）为例：

| 操作 | 以 A 身份 | 以 S 身份 |
|---|---|---|
| 开户 / 停用账号 | 允许 | **拒绝** |
| 重置他人口令 | 允许 | **拒绝** |
| 下载备份 | 允许 | **拒绝** |
| 导入课表 / 名单 | **拒绝** | 允许 |
| 修改 L1 参数 | **拒绝** | 允许 |
| 确认他人课务 | 拒绝 | 拒绝 |
| 代替教师发起调课 | 拒绝 | 拒绝 |

最后两行不随身份变化：它们由 `teacherId` 与角色共同决定，`admin` 两样都不满足。

## 5. 当前正式库的状态

| 账号 | 角色 | 说明 |
|---|---|---|
| `admin` | A + S | 登录需选身份；A 做账号运维，S 做资料导入 |
| `staff` | S | 课务管理人员，只做业务资料 |

`admin` 追加 S 的时间点与理由见 `GRANT_ROLE` 审计（`afterState=S`）。

## 6. 仍然没做的

| 项 | 状态 |
|---|---|
| 网页上的导入入口 | 未做，导入仍在命令行 |
| 代教师发起调课 | **明确不做**；如需"代录"，另立方案（方案须记 `onBehalfOf`，确认仍由教师本人做） |
| 撤销角色 | 表结构有 `revoked_at`，但没有入口；目前只能追加，不能收回 |
