# 忘记口令怎么办：管理员重置（P7D）

- 状态：**本文件是本项目提出的操作方式，不是学校已确认的制度**。
- 覆盖：教师（或任何账号）忘记登录口令后，由管理员恢复其登录能力。
- 不覆盖：自助找回。系统不采集手机号、不接外部身份源，第一版纯内网，**没有短信/邮件找回**。

---

## 1. 为什么只能管理员重置

口令找回的常规做法是"验证你是你"：发短信到预留手机号、发邮件到预留邮箱。
这些系统都没有——建号时只登记了账号、姓名、教师编号，没有任何可用于远程核身份的联系方式。

所以只剩一条路：**本人到管理员处，管理员当面核身份后重置**。
这条路的代价是管理员会成为工单点，所以在设计上要把它压到最轻：

- 重置后本人**必须自己改密**，管理员看不到、也不需要看到本人后续用的口令；
- 每次重置都必须填**理由**，写进审计，事后能追问"这次为什么重置、谁核的身份"；
- 一次性口令由系统生成，不复用、不外传。

## 2. 重置会发生什么

| 项 | 结果 |
|---|---|
| 新口令 | 系统生成的随机一次性口令（12 位以上，字母+数字，各不相同） |
| 旧会话 | 目标账号**所有已登录会话立即失效**（`PASSWORD_RESET`） |
| 首次登录 | 必须改密；未改密前除改密外一律拒绝 |
| 审计 | 记 `action=RESET_PASSWORD`、`actor=管理员`、`objectId=被重置账号`、`afterState=MUST_CHANGE`、`reason=填写的理由` |
| 管理员所知 | 只知道这一次的一次性口令；本人改密后管理员无从得知 |

## 3. 谁可以做

权限矩阵里 `RESET_PASSWORD` 只有**系统管理员（A）**是 ALLOW，其余角色（T / S / C / R / J）全部 DENY。
课务管理人员管业务，不管账号口令；这是两件事。

另外两条硬限制：

- **不能重置当前登录账号自己的口令**（`CANNOT_RESET_SELF`）。改自己的口令有改密功能，
  它要求输入旧口令——这道校验不能被重置绕过；而且重置会当场吊销操作人自己的会话。
- **已停用的账号不给重置**。停用账号重置后依然登不进来，只会造成"重置了还是进不去"的误解。
  目前没有恢复启用的入口，所以这一步必须先人工确认该账号是否该重新启用。

禁止的只是"重置自己"：两名管理员之间可以互相重置。所以**至少要设两名管理员**——
否则唯一的管理员忘记口令时，谁都没有权限帮他重置。

## 4. 怎么用

```bash
CA_DB_PATH=/data/ca.sqlite \
CA_ADMIN_LOGIN=admin \
CA_ADMIN_PASSWORD='管理员口令' \
CA_TARGET_LOGIN=t005 \
CA_REASON='本人到办公室申请并核验证件' \
npm run reset-password
```

| 变量 | 必填 | 说明 |
|---|---|---|
| `CA_DB_PATH` | 是 | 库路径；**未设定环境的库直接拒绝**（须先 `npm run set-mode`） |
| `CA_ADMIN_LOGIN` / `CA_ADMIN_PASSWORD` | 是 | 执行人身份；口令仅用于本次登录，不落盘、不入日志 |
| `CA_TARGET_LOGIN` | 是 | 被重置的账号名 |
| `CA_REASON` | 是 | 重置理由，写入审计 |
| `CA_OUT_FILE` | 否 | 另写一份结果文件，权限 `0600` |

执行人必须具 `RESET_PASSWORD` 权限，且**自己已完成首登改密**（未改密的管理员不能执行任何管理动作）。

退出码：`0` 成功；`1` 登录失败 / 账号不存在 / 账号已停用 / 权限不足；`2` 缺必填环境变量。

## 5. 交付与留痕建议

1. 重置后把新口令**当面**交给本人（打印纸条或口头），不要把清单群发。
2. 让本人当场登录并改成自己的口令；改完即作废那张纸条。
3. 理由写具体（"本人到场+核验"而不是"重置"），将来查审计时能说清这次操作的依据。

## 6. 仍然是缺口的项

| 项 | 说明 |
|---|---|
| 恢复启用已停用账号 | 没有入口；停用目前不可逆，误停用需人工核对后另行处理 |
| 唯一管理员忘记口令 | 没有入口：`init-admin` 只在空库可用。缓解办法是至少设两名管理员（见 §3） |
| 网页端重置按钮 | 未做。账号管理类操作走命令行，管理员账号不必常驻浏览器登录态 |
| 批量重置 | 未做。逐个执行，每次都要单独填理由 |
