# 局域网访问说明（2026-11-03）

## 1. 为什么 `127.0.0.1` 别人打不开

`127.0.0.1` 是**回环地址**，只在本机内部有效，数据包不出网卡。服务绑定它时，
只有这台机器自己的浏览器能访问；其他老师的手机、电脑发来的请求**根本到不了这个进程**。

实测对比（同一台机器）：

| 访问地址 | 绑定 `127.0.0.1` | 绑定 `192.168.x.x` |
|---|---|---|
| `http://127.0.0.1:18089` | 200 | 连不上 |
| `http://192.168.x.x:18089` | **连不上** | 200 |

两者是互斥的：绑定具体 IP 后，回环地址反而不再可达。这是操作系统行为，不是程序缺陷。

## 2. 当前部署

> 本文出现的 `192.168.x.x` 与 `<DB_PATH>` 都是占位符：本仓库公开，不写实际地址与库位置。
> 你机器上的实际值由 `npm run serve:auto -- --status` 打印。

| 环境 | 地址 | 库 | 是否常驻 |
|---|---|---|---|
| 正式业务 | `http://192.168.x.x:18089` | `<DB_PATH>/ca-production/school.sqlite` | 是 |
| 演示 / 联调 | `http://192.168.x.x:18088` | `<DB_PATH>/ca-demo/demo.sqlite` | **否，按需启动** |

演示库只是一个可再生的沙盒：库内没有真实数据，`npm run seed:demo` 可以随时重建。
它日常不占端口、不占进程，只在培训、演示或 T-04 两环境对照时临时拉起。
理由是双实例常驻会让排查变成两倍——今天遇到过一次两个实例同时挂掉，
两个端口都要查、两份日志都要翻，而演示实例那半天没有任何一次真实操作。

该地址是本机 `wlan0` 在校园 WiFi 中的地址，**会随 DHCP 变化**，所以不要写死在任何地方。

启动命令（推荐用自愈脚本，地址变了不用手工改）：

```bash
npm run serve:auto                      # 对齐一次：只保证正式实例，已在跑且地址正确就什么都不做
npm run serve:auto -- --status          # 只看状态，不动进程
npm run serve:auto -- --watch           # 常驻看守：地址变了或进程挂了自动重启
npm run serve:auto -- --stop-demo       # 只停演示实例，正式实例不受影响

# 需要演示实例时（培训、验收两环境对照）
CA_WITH_DEMO=1 npm run serve:auto
```

脚本做的事：读 `wlan0` 当前地址 → 校验是私有地址 → 需要的实例都健康就退出，
否则停掉旧进程、按新地址重启并等到真正可访问（判定是页面含 `id="app"`，不是端口通）。
日志写在 `.run/prod.log`、`.run/demo.log`，进程用 `nohup` 拉起，**关掉终端不会停**。

注意两点：

- 默认模式**不会主动去杀**已经跑着的演示实例，只是不纳入看守。要停用 `-- --stop-demo`，
  免得“我只想看看状态”变成“顺手把别人开着的演示环境关掉”。
- 当 `CA_WITH_DEMO=1` 且演示实例需要拉起时，脚本会连正式实例一起重启。
  这是有意的：新旧两套进程同时绑一个库比中断两秒更危险。

### 2.1 从系统自带终端启动（exit 127 / Operation not permitted）

桌面上只放一个 `启动课务系统.sh`（不再配 `.desktop`：本机没有
`/usr/share/applications`，文件管理器不认 `.desktop`，双击只会弹“打开方式”）。

正确启动方式是一条命令：

```bash
cd ~/Desktop && sh 启动课务系统.sh
```

两个坑：

| 现象 | 原因 | 处理 |
|---|---|---|
| `command not found: bash`，退出码 127 | 自带终端的 `PATH` 里没有 node 与 bash | 脚本已在内部补齐，见下表 |
| `./启动课务系统.sh: Operation not permitted` | 该目录下直接执行被拒绝（执行位/沙箱限制） | 用 `sh 启动课务系统.sh`，由 sh 读文件解释，不需要执行位 |

依赖位置：

| 依赖 | 位置 | 自带终端里是否在 PATH |
|---|---|---|
| `bash` | `/data/storage/el1/bundle/libs/arm64/bash/bin/bash` | 否 |
| `node` / `npx` | `/data/storage/el1/bundle/libs/arm64/node/bin` | 否 |
| `curl` `ps` `awk` `nohup` | `/usr/bin`、`/bin` | 是 |

处理办法已经写进脚本本身，无需手工改 PATH：

- `启动课务系统.sh` 先把上面两个目录补进 `PATH`，再用绝对路径找 `bash` 兜底；
  找不到就明确打印“预期位置”，不再只丢一句 `command not found`。
- `scripts/serve-auto.sh` 顶部同样补 `PATH`，所以直接 `bash scripts/serve-auto.sh`
  也不会在拉起实例那一步报 `npx: not found`。

另有一个连带问题：本机 `/tmp` 属于 `root:expert`、普通用户不可写，而 `tsx`
启动时要在临时目录建 `unix socket`。自带终端不设 `TMPDIR` 时会落到 `/tmp` 并报
`EACCES: permission denied /tmp/tsx-*.pipe`。`serve-auto.sh` 会在 `TMPDIR`
不可写时改指 `/data/storage/el2/base/cache`。

需要手工指定时（脚本不覆盖的场合）：

```bash
# 正式
CA_BIND_ADDRESS=192.168.x.x CA_PORT=18089 \
CA_DB_PATH=<DB_PATH>/ca-production/school.sqlite \
npm run serve

# 演示（按需，不常驻；用完 Ctrl-C 或另开一个终端跑 --stop-demo）
CA_BIND_ADDRESS=192.168.x.x CA_PORT=18088 \
CA_DB_PATH=<DB_PATH>/ca-demo/demo.sqlite \
npm run serve
```

注意：`--watch` 看守进程自身不是守护服务，关掉它所在的终端就停了；
服务进程不受影响。要开机自启，需要把 `npm run serve:auto` 挂到系统启动项。

## 3. 四个前提，缺一个老师照样打不开

| # | 前提 | 不满足时的现象 | 怎么处理 |
|---|---|---|---|
| 1 | 这台机器常开、不休眠 | 页面转圈直到超时 | 关掉自动休眠；不要关终端窗口 |
| 2 | IP 固定 | 某天起所有人打不开，但服务在跑 | 路由器上按 MAC 做 DHCP 保留，或系统设静态 IP |
| 3 | 无线客户端隔离（AP Isolation）关闭 | 本机能开，手机打不开 | 由网络管理员在 AP/路由器侧关闭该功能 |
| 4 | 防火墙放行 18089 / 18088 | 同网段 ping 得通但端口连不上 | 放行入站 TCP |

第 3 条在校园 WiFi 里很常见，且**只能在客户端侧验证**：手机连同一个 WiFi，
浏览器打开 `http://192.168.x.x:18089`，能出登录页即说明未隔离。

> 2026-11-02 晚：本机 WiFi 网段变化，地址由 `192.168.11.x` 变成 `192.168.3.x`，服务按新地址重启。
> 2026-11-03 早：WiFi 重连后又回到 `192.168.11.x`，服务再次按新地址重启。
> 这正是第 2 条前提（IP 固定）未满足的情形：地址会来回跳，根治办法是路由器上按 MAC 做 DHCP 保留或系统设静态 IP。

## 4. IP 变了怎么办

服务启动时绑定的是**那一刻的地址**，地址变了不会自动跟随。判断方法看启动日志第一行：

```
已启动：http://192.168.x.x:18089　数据库=...　审计条数=...
```

按新地址重启即可，数据不受影响（库是文件，与地址无关）：

```bash
npm run serve:auto     # 自动读当前地址，只重启地址不对的实例
```

`--watch` 常驻时不需要人工介入，地址一变自动切过去。

> 实测（2026-11-03）：手动杀掉全部服务进程后执行 `serve:auto`，
> 4 秒内两个实例恢复，进程父 PID 为 1（`nohup` 生效，关终端不退出）。

根治办法仍是第 2 条前提里的 DHCP 保留或静态 IP——脚本只是让人不必每次手工查地址。

## 5. 安全边界（未放松）

- 配置校验只接受**私有地址**（`10.`、`172.16–31.`、`192.168.`、回环）与私有 IPv6；
  `0.0.0.0`、`::`、公网地址一律拒绝启动（`src/server/config.ts:87`，P5-1）。
- 不接受主机名，避免域名被改指向公网。
- 因此本次改动只是把可见范围从"本机"扩到"同一内网段"，**没有**扩到公网。

**已知风险**：当前为明文 HTTP，启动日志会打印警告。口令与课表在同一 WiFi 内以明文传输，
技术上可被同网段嗅探。首版按 T-03（内网 HTTPS）未关闭处理，正式对全校开放前应补齐。
