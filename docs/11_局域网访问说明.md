# 局域网访问说明（2026-11-02）

## 1. 为什么 `127.0.0.1` 别人打不开

`127.0.0.1` 是**回环地址**，只在本机内部有效，数据包不出网卡。服务绑定它时，
只有这台机器自己的浏览器能访问；其他老师的手机、电脑发来的请求**根本到不了这个进程**。

实测对比（同一台机器）：

| 访问地址 | 绑定 `127.0.0.1` | 绑定 `192.168.11.28` |
|---|---|---|
| `http://127.0.0.1:18089` | 200 | 连不上 |
| `http://192.168.11.28:18089` | **连不上** | 200 |

两者是互斥的：绑定具体 IP 后，回环地址反而不再可达。这是操作系统行为，不是程序缺陷。

## 2. 当前部署

| 环境 | 地址 | 库 |
|---|---|---|
| 正式业务 | `http://192.168.11.28:18089` | `ca-production/school.sqlite` |
| 演示 / 联调 | `http://192.168.11.28:18088` | `ca-demo/demo.sqlite` |

`192.168.11.28` 是本机 `wlan0` 在校园 WiFi 中的地址。

启动命令：

```bash
# 正式
CA_BIND_ADDRESS=192.168.11.28 CA_PORT=18089 \
CA_DB_PATH=/data/storage/el2/base/cache/ca-production/school.sqlite \
npm run serve

# 演示
CA_BIND_ADDRESS=192.168.11.28 CA_PORT=18088 \
CA_DB_PATH=/data/storage/el2/base/cache/ca-demo/demo.sqlite \
npm run serve
```

## 3. 四个前提，缺一个老师照样打不开

| # | 前提 | 不满足时的现象 | 怎么处理 |
|---|---|---|---|
| 1 | 这台机器常开、不休眠 | 页面转圈直到超时 | 关掉自动休眠；不要关终端窗口 |
| 2 | IP 固定 | 某天起所有人打不开，但服务在跑 | 路由器上按 MAC 做 DHCP 保留，或系统设静态 IP |
| 3 | 无线客户端隔离（AP Isolation）关闭 | 本机能开，手机打不开 | 由网络管理员在 AP/路由器侧关闭该功能 |
| 4 | 防火墙放行 18089 / 18088 | 同网段 ping 得通但端口连不上 | 放行入站 TCP |

第 3 条在校园 WiFi 里很常见，且**只能在客户端侧验证**：手机连同一个 WiFi，
浏览器打开 `http://192.168.11.28:18089`，能出登录页即说明未隔离。

## 4. IP 变了怎么办

服务启动时绑定的是**那一刻的地址**，地址变了不会自动跟随。判断方法看启动日志第一行：

```
已启动：http://192.168.11.28:18089　数据库=...　审计条数=...
```

若实际 IP 已不是这个，按新地址重启即可，数据不受影响（库是文件，与地址无关）。
根治办法是第 2 条前提里的 DHCP 保留。

## 5. 安全边界（未放松）

- 配置校验只接受**私有地址**（`10.`、`172.16–31.`、`192.168.`、回环）与私有 IPv6；
  `0.0.0.0`、`::`、公网地址一律拒绝启动（`src/server/config.ts:87`，P5-1）。
- 不接受主机名，避免域名被改指向公网。
- 因此本次改动只是把可见范围从"本机"扩到"同一内网段"，**没有**扩到公网。

**已知风险**：当前为明文 HTTP，启动日志会打印警告。口令与课表在同一 WiFi 内以明文传输，
技术上可被同网段嗅探。首版按 T-03（内网 HTTPS）未关闭处理，正式对全校开放前应补齐。
