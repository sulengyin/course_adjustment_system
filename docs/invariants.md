# 业务不变量（L0）

> 定义：任何配置、任何角色、任何时间点都必须成立；代码中作为断言，测试中作为元测试的靶子。
> 每条格式：**给定 X，结果不得为 Y。**

| ID | 不变量 | 反例（必须失败） | 对应测试 |
|---|---|---|---|
| INV-01 | 沉默/已读/未回复/过期 **≠** 同意；旧版本确认不得沿用到新版本 | 已读未答 → 判为同意 | AC03、AC06 |
| INV-02 | 临时登记 **≠** 教师接受 **≠** 正式生效 **≠** 已执行 | 登记后直接改课表 | AC10、AC04 |
| INV-03 | 口头登记 **≠** 本人电子确认；补确认不得倒填时间；任何人不得替他人确认 | 第三方转述即生成确认 | AC05、AC11 |
| INV-04 | 协调结案 **≠** 授课事实已核验 **≠** 课程已完成 | 结案后自动清除待核验待办 | V23-11 |
| INV-05 | 导入文件 **≠** 学校正式发布 | 上传即标记 `OFFICIAL` | AC01 |
| INV-06 | 已执行授课事实不得被恢复方案改写 | 恢复方案覆盖已完成课次 | V23-05 |
| INV-07 | 必要确认者由受影响集合计算，不由发起人指定；班主任不自动成为确认者 | 发起人自选确认人 | V23-03 |
| INV-08 | 系统管理员不代确认、不默认裁决、不因技术权限获得业务权 | 管理员点"确认"生效 | V23-13 |
| INV-09 | 生效后不可删除；取消须新建方案并重新确认 | 删除已生效变更 | 见 P4 |
| INV-10 | 纯资料纠错不得改变实际授课/工作责任 | 以"纠错"替换任课教师 | AC07、V23-06 |
| INV-11 | 无占用记录 **≠** 有空；有空 **≠** 愿意 | 空课即判"可代课" | AC02 |
| INV-12 | 服务端逐操作、逐资源校验；前端隐藏不算授权 | 依赖隐藏入口做权限 | V23-13 |
| INV-13 | 第一版纯校内访问，校外不得直连 | 校外可打开登录页 | AC12 |
| INV-14 | 任何变更不得静默覆盖已生效事实；重试不得重复生效 | 新导入覆盖调课 | AC08、V23-12 |

## 不变量与其他约束的关系

- L0 不因 L1 配置或 L2 制度开关而失效（CFG-09 已验证）。
- L1 只影响**时间、阈值、格式、范围**；一旦某个键的取值会改变"谁算同意/什么算生效"，它就不是 L1。
- L2 只能开启"学校已书面决定"的行为，且开启动作本身写入审计。

## 禁止的推导（常见越界）

| 从 | 不得推出 |
|---|---|
| 课表无课 | 教师有空 |
| 教师有空 | 愿意代课 |
| 教师同意方案 A | 同意方案 A' |
| 请求已送达 | 有人承接 |
| 已读 | 已同意 |
| 已登记 | 已生效 |
| 已安排 | 已执行 |
| 已结案 | 已上课 |
| 已提交 | 可结算 |
| 导入成功 | 学校已发布 |
| 纠错完成 | 责任未变 |

## 维护规则

- 新增不变量须同时新增：反例场景、变异体（`spec/engine/mutants.ts`）、追溯行。
- 删除或弱化不变量需项目负责人书面同意，并记录在 `docs/decisions.csv`。
