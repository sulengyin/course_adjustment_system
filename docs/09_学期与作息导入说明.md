# 学期与作息导入（P7E）

- 状态：**导入机制已实现；2026—2027 学年第一学期的数据待执行**（缺执行人口令，见 §6）。
- 覆盖：真实学期（起止）与每天第 1–N 节课的起止时间。
- 不覆盖：大课间、眼保健操、午餐午休、课后服务时段；课表模板；班级与科目。

---

## 1. 为什么先导作息

课表生成时按 `period` 去作息表（`bell`）查起止时间，查不到就把课次标成
`BELL_NOT_CONFIGURED`（时间未知）。没有作息，导进来的课表只有"第几节、哪个班"，
没有"几点到几点"，教师看到的是一张不能执行的表。

系统里一个库只能有一个学期，学期被课表引用后再改，历史课表的时间会被重新解释。
所以学期和作息一起导，且**已有学期就拒绝覆盖**。

## 2. 只收课节，不收课间

| 真实作息里的项 | 是否入 `bell` | 原因 |
|---|---|---|
| 第一节 … 第七节 | 是 | 有课，需要起止时间 |
| 大课间、升旗仪式 | 否 | 不是课节，入表会被课表当成一节课 |
| 眼保健操 | 否 | 同上 |
| 午餐、午休 | 否 | 同上 |
| 课后服务第一/第二时段 | 否 | 属于课后服务，不是正式课节；待课后服务模型建立后单独落库 |

课间与午餐不落库不影响课表：第 2 节 09:30 开始，本身就说明了第 1 节 09:00 结束。

## 3. 输入格式

```csv
period,starts_at,ends_at
1,08:20,09:00
2,09:30,10:10
```

- 列名必须完全一致，缺列直接报错。
- `period` 必须是正整数且**从 1 连续**，缺一节即拒绝（不允许跳号）。
- 时间 `HH:MM`（24 小时制），结束必须晚于开始。

## 4. 硬校验

| 校验 | 拒绝码 |
|---|---|
| 学期名称为空 | `EMPTY_LABEL` |
| 日期格式不是 `YYYY-MM-DD` | `BAD_DATE` |
| 起始日不是周一 | `START_NOT_MONDAY` |
| 结束日早于起始周一 | `END_BEFORE_START` |
| 第一周单双周不是 ODD/EVEN/未声明 | `BAD_PARITY` |
| 作息为空 | `EMPTY_BELL` |
| 节次不是正整数 | `BAD_PERIOD` |
| 节次不从 1 连续 | `PERIOD_NOT_SEQUENTIAL` |
| 时间格式不是 `HH:MM` | `BAD_TIME` |
| 结束不晚于开始 | `END_NOT_AFTER_START` |
| 库中已有学期 | `TERM_EXISTS` |

起始日必须是周一：学期第几周、单双周都从周一起算，不是周一会让整学期的周次错位。

第一周单双周留空表示**学校未声明**，系统不会默认按单周处理——单双周课程会因此无法判定。

## 5. 怎么执行

```bash
CA_DB_PATH=/data/ca.sqlite \
CA_ACTOR_LOGIN=staff \
CA_ACTOR_PASSWORD='课务口令' \
CA_TERM_LABEL='2026—2027学年第一学期' \
CA_TERM_START_MONDAY=2026-08-31 \
CA_TERM_END_DATE=2027-01-22 \
CA_BELL_CSV=/data/bell-2026-2027-1.csv \
npm run import-bell
```

| 变量 | 必填 | 说明 |
|---|---|---|
| `CA_DB_PATH` | 是 | 必须是已设定为 PRODUCTION 的库 |
| `CA_ACTOR_LOGIN` / `CA_ACTOR_PASSWORD` | 是 | 执行人须具 `IMPORT_TIMETABLE` 权限（课务 S）；**管理员 A 不能代管** |
| `CA_TERM_LABEL` | 是 | 学期名称 |
| `CA_TERM_START_MONDAY` | 是 | 第一周周一 |
| `CA_TERM_END_DATE` | 是 | 最后一天（含） |
| `CA_BELL_CSV` | 是 | 作息 CSV |
| `CA_TERM_FIRST_WEEK` | 否 | `odd` / `even`；留空 = 未声明 |

导入结果：`term` 与 `bell` 的 `data_origin` 都是 `IMPORTED_UNVERIFIED`，
审计记 `IMPORT_TERM`（含学期、节数、起止日期）。**真实作息不等于官方核定时间**，
校方核对后要走显式变更，不能靠重导覆盖。
