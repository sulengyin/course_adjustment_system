## 1. 负责人已裁定（4 项）

| # | 事项 | 裁定 | 影响 |
|---|---|---|---|
| J1 | 首版交付范围 | **只读课表 + 导入发布 + 线上调课协商 + 审计历史**；应急代课模块待 D04/D07 关闭后进入 | P6 不进首版；首版 14 条 AC 中的应急类用例（AC04/AC11）仅作契约验证，不作为首版上线门槛 |
| J2 | 登录方式 | **本地账号 + 管理员开户**：管理员建号发初始密码、首登强制改密、支持重置与离职停用；不采集手机号 | 权限主体为 `Principal`，无钉钉/短信依赖 |
| J3 | 离线与同步 | **断网明确失败 + 幂等重试**；不做离线写队列，不做只读离线缓存 | API 只需幂等键，不需同步游标/墓碑 |
| J4 | 待定规则默认值 | **空值必填**；未配置即 `NOT_CONFIGURED` | L1 全部 `defaultValue: null`，已由测试断言 |

## 2. 架构默认（可逆，未经反对即执行）

| # | 默认 | 触发原因 |
|---|---|---|
| A1 | 禁止直接修改课次，一切变更走 `change_case` | 防止绕过确认改课表 |
| A2 | 结构性冲突（同教师/同班级同时段两课）永远硬；占用类冲突按 L1 `conflict.severity` | 前者是事实矛盾，后者是学校口径 |
| A3 | 仅教师本人可发起自己的调课；授权人员只能登记应急安排 | 防止"代发起"演变为"代同意" |
| A4 | 查看他人课表仅显示姓名/班级/学科/时间/课次类型 | 私人理由不公开 |
| A5 | 不采集手机号、不存学生名单 | 最小化；首版无短信通道 |
| A6 | 不做教师"全局意愿"开关 | 长期偏好会被误读为对具体方案的同意 |
| A7 | "已执行"只接受授权人员显式登记 | BIZ-03 未定，不按时间推断 |
| A8 | 连堂 = 多个单节课次 + 连堂标记 | 避免只能整段调、不能调半节 |
| A9 | 审计 append-only + 事件哈希链 | 满足"不可抹除"且成本可控 |
| A10 | 一人多角色须显式 `actingAs`，否则拒绝 | 防止权限叠加越权 |

## 4. 由此产生的契约约束（已写入代码）

1. `spec/config/schema.ts`：L1 全部 `defaultValue: null`；L2 全部 `defaultEnabled: false` 且 `requiresBasisDocument: true`。
2. `spec/config/schema.ts`：`enablePolicy()` 对 L0 直接拒绝（`L0_NOT_CONFIGURABLE`），无依据拒绝（`BASIS_REQUIRED`）。
3. `spec/engine/reference.ts`：`SIMULATED` 数据永不 `official`。
4. `spec/engine/reference.ts`：外部网络一律 `DENIED_EXTERNAL`。
5. `spec/engine/reference.ts`：`authorize()` 中管理员执行 `CONFIRM` 一律拒绝。
6. `spec/engine/reference.ts`：`closeCase()` 拒绝自审自批。
