## 2. 本阶段允许实现的范围与拒绝猜测的事项

**允许**：契约类型、判定函数、配置 schema、反例与元测试、追溯矩阵、决策台账。全部使用虚构数据。

**拒绝猜测**（本阶段一律返回显式状态，不产生业务默认值）：

| 事项 | 实现方式 |
|---|---|
| 线下调课单/口头同意的生效判定（D01/D02） | `thirdPartyClaim` 无依据 → `REJECTED`；有依据也只到 `RECORDED_PENDING` |
| 新版课表与既有变更重叠（D03） | `importBatch` 有冲突 → `CONFLICT`，`overwritten:false` |
| 争议裁决（D04） | 无裁决接口；权限矩阵标 `TBD_BLOCKED` |
| 接单先后裁定（O2-1） | 来源不同 → `AMBIGUOUS` + `requiresAdjudication:true` |
| 未接听/未送达处置（O4-1） | 仅"明确拒绝"立即升级；其余返回 `NOT_CONFIGURED` |
| 轮换课推算（BIZ-06） | 恒返回 `UNKNOWN_ROTATION` |
| 纠错白名单（BIZ-01） | 识别为 `FACTUAL_CORRECTION`，但 `whitelistStatus=NOT_CONFIGURED` |
| 已执行判定（BIZ-03） | 仅接受显式登记，不按时间推断 |
| 配置默认值（J4） | L1 全部 `null`，未配置 → `NOT_CONFIGURED` |

## 3. 设计取舍与对应需求

| 取舍 | 需求 ID | 理由 |
|---|---|---|
| 判定函数全部为纯函数，无 DB/HTTP/时间依赖 | G5、G6 | 使反例可被变异测试攻击；时间作为入参保证可复现 |
| 用 `Outcome` 枚举代替布尔 | D5、E1、INV-02 | "未确认"与"拒绝"必须可区分，布尔会丢失语义 |
| 配置分 L0/L1/L2，L0 不进 schema | A6、D04、J4 | 防止"管理员改配置 = 改制度" |
| `SIMULATED` 永不 `official` | J1、R05 §0.7 | 模拟数据不得冒充学校正式数据 |
| 拒绝自审自批 | V2.3 必测 11 | 提交与批准必须分离；BIZ-05 未定时取更严一侧 |
| 一人多角色需 `actingAs` | A5、A6 | 防止权限叠加后越权 |

## 6. 引入的假设与风险

| # | 假设/风险 | 影响 |
|---|---|---|
| 1 | 测试语言选 TS/Vitest，仅用于契约层 | 若后续后端选 Python，`spec/` 需重写；契约文档与 CSV 不受影响 |

| 3 | 拒绝自审自批是"取更严一侧"，非学校已定规则 | 若 BIZ-05 允许同人，需改一处判定并更新 V23-11 |

| 5 | V2.3 场景 7/8 尚未自动化 | P2/P6 必须补上，否则不得宣称全覆盖 |
