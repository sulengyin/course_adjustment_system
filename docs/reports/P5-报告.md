## 2. 网络边界

### 2.1 配置校验（`src/server/config.ts`）

启动前强制三条，任一不满足即退出码 2，不存在"先明文跑起来"的分支：

1. 绑定地址必须是 **IP 字面量**，不接受主机名（主机名可能被改指向公网）。
2. `0.0.0.0` / `::` / `::0` 一律拒绝（`WILDCARD_BIND`）。
3. 非回环、非私有网段一律拒绝（`PUBLIC_BIND`）：IPv4 仅 `127/8`、`10/8`、`172.16/12`、`192.168/16`；IPv6 仅 `::1`、`fc00::/7`、`fe80::/10`。
4. `CA_REQUIRE_TLS=1` 而未提供证书 → 拒绝启动（`TLS_REQUIRED_BUT_MISSING`）；证书或私钥文件不存在 → 拒绝启动。

监听完成后还会核对 `server.address()` 与配置是否一致，不一致直接关闭并报错，避免"以为绑在 127.0.0.1、实际在 ::1"。

### 2.2 实测结果

| 场景 | 结果 |
|---|---|
| `CA_BIND_ADDRESS=0.0.0.0` | exit 2，`WILDCARD_BIND` |
| 端口被占用 | exit 3，`启动失败：listen EADDRINUSE ...` |
| `127.0.0.1:18080` | 正常启动，`healthz` 返回审计链状态 |
| 启动日志 | `SERVER_STARTED` 仅含 address/port/tls/审计条数 |

**未实测**：校外移动数据访问（AC12）、公网暴露扫描（T-07）、教师 Wi-Fi 可达性（T-01）。这三项需要真实网络与设备，按 `NOT_RUN` 记录，不得据此宣称"网络边界已验收"。

## 3. 身份与会话（R-25 修复）

### 3.1 身份只从会话来

- `Principal` 是品牌类型，只能由 `mintPrincipal` 产生；`tests/boundary.spec.ts` 静态扫描 `src/`，确认除 `src/auth/` 外无人调用。
- HTTP 层只读取 `Authorization: Bearer <token>`；请求体里的 `teacherId` / `submittedBy` 不读。已有用例直接投毒这两个字段并断言操作人仍是登录者。
- 会话表只存 token 的 SHA-256，不存明文；token 一次性展示。

### 3.2 已实现的会话规则

| 规则 | 行为 |
|---|---|
| 空闲超时 | 默认 30 分钟（技术基线，可配置） |
| 一人多角色 | 未指定身份 → `AMBIGUOUS_ROLE`；指定未授予身份 → `ROLE_NOT_GRANTED` |
| 切换身份 | 作废旧会话 |
| 停用账号 | 立即吊销全部会话 |
| 重置口令 | 旧会话全部失效，且强制下次登录改密 |
| 首登未改密 | 仅允许 `/api/me`、`/api/me/password`、`/api/auth/logout`，其余 403 |
| 改密 | 校验强度与"不得复用旧口令"，成功后所有会话作废 |

### 3.3 权限矩阵不因"管理员"放宽

`src/auth/policy.ts` 逐操作 × 逐角色表驱动，无超级角色分支：

- 发布课表：S 角色为 `TBD_BLOCKED`（AC01 未关闭），管理员也为 `DENY`。
- 确认本人课务：按教师身份判定，管理员 `DENY`（INV-08）。
- 录入执行事实、开启 L2 政策：`TBD_BLOCKED`。

## 4. 审计链与备份恢复

### 4.1 审计唯一写入口（`src/store/audit-log.ts`）

- 业务模块不得直接 `INSERT INTO audit_event`，只能经 `AuditLog.append`。
- 每行 `hash = sha256(seq|at|actor|action|objectType|objectId|before|after|reason|prevHash)`，`prev_hash` 串成链。
- `BEFORE UPDATE` 触发器拒绝改行；`verify()` 从头重算，能发现改行、删行、换序、未封印行。
- 私人理由留在 `change_case.reason`，不进审计（`tests/boundary.spec.ts` 用"家中老人住院"样本断言审计表零命中）。

**已知边界**：哈希链无法发现"整段尾部被截断"。因此备份清单记录当时的 `length` 与 `lastHash`，由恢复对账做锚点；测试覆盖"截掉尾部并同步改 sha"仍被 `TALLY_MISMATCH` 发现。

### 4.2 备份与恢复

- 备份用 `VACUUM INTO` 生成一致性快照，不拷贝运行中的库文件；目录 0700、库文件与清单 0600。
- 清单记录 sha256、字节数、schema 版本、13 项对账数据（教师/班级/课次/确认/审计长度/末哈希等），从**备份副本**读取而非源库。
- 文件被改 → `SHA_MISMATCH`；改行后重签 sha → `AUDIT_CHAIN_BROKEN`；截尾后重签 → `TALLY_MISMATCH`；清单缺失或形状不合法 → `MANIFEST_UNREADABLE`，拒绝恢复。
- 默认拒绝覆盖目标文件，必须显式 `CA_OVERWRITE=1`；恢复后再对账一次。
- 备份目录不得包含正在使用的数据库文件（防止备件与活库混放）。

### 4.3 恢复演练（AC14 支撑）

`npm run smoke:deploy` 在独立临时目录完成：

```
备份完成：.../backup/backup-<时间戳>.sqlite
  sha256=e82b5f97...
  审计条数=4　末哈希=290ee38f...
恢复完成：.../restored.sqlite
  审计条数=4　链完整=true　末哈希=290ee38f...
重复恢复未声明覆盖: exit=1 恢复失败：TARGET_EXISTS
600 .../backup/backup-<时间戳>.sqlite
600 .../restored.sqlite
```

教师数/课次数等业务数据本次演练为 0（空库 + 管理员开户 + 登录审计），对账字段齐全但**未覆盖真实规模数据**；真实数据恢复演练需等校方提供备份窗口（T-09）。

## 6. 本轮边界审查发现并修复的问题

按"畸形输入不得触发有后果的动作、外部文件不得让程序崩溃"逐项检查，发现 7 处并已修复，均有测试：

| # | 问题 | 原行为 | 现行为 | 证据 |
|---|---|---|---|---|
| 1 | 确认接口对未知 `decision` 取值 | 非 `DECLINE` 一律当 `ACCEPT`，拼写错误 = 一次不可撤销的接受 | 只接受 `ACCEPT` / `DECLINE`，其余 400 `BAD_INPUT` | `tests/server/http.spec.ts`「确认决定只接受…」 |
| 2 | 变更条目形状未校验 | `items` 为字符串/对象时在服务层抛 TypeError → 500 | 逐项校验类型与 `kind` 枚举，畸形 400 | 同上「畸形变更条目返回 400」 |
| 3 | 响应已开始写出后再抛错 | `writeHead` 触发 `ERR_HTTP_HEADERS_SENT`，可能带崩进程 | `headersSent` 时直接断开连接 | 代码级防护（难以稳定构造用例） |
| 4 | 备份清单形状未校验 | 合法 JSON 但字段缺失 → 对账时 TypeError | 形状不合格按 `MANIFEST_UNREADABLE` 处理 | `tests/backup/backup.spec.ts`「清单形状不合法…」 |
| 5 | 备份/恢复文件权限跟随 umask | 宽松环境可能是 0644（含个人材料与口令哈希） | 显式 `chmod 0600` | 同上「备份与恢复出的库文件权限固定为 0600」 |
| 6 | 日志方法依赖 `this` | 解构后调用抛 TypeError | 闭包实现，解构可用 | `tests/log/logger.spec.ts`「方法被解构后仍可调用」 |
| 7 | 空幂等键 | 第二次写入撞 `UNIQUE(idempotency_key)` 报 500，或被他人的空键方案误判为重复 | HTTP 要求非空（400）；服务层把空串存 NULL，不再互相顶替 | `tests/server/http.spec.ts`「写接口缺少幂等键」；`tests/service/change.spec.ts`「空幂等键按未提供处理」 |

另外修正两处部署脚本缺陷：

- `serve.ts` 启动失败（端口占用等）原本是未捕获异常；现输出明确错误并以 exit 3 退出，同时关闭数据库。
- `backup.ts` 的"备份目录保护"条件方向写反且仅对绝对路径生效；现按 `resolve()` 后判断，语义与提示一致。
