## 2. 流程与状态

```
上传 ──解析失败/校验失败──> REJECTED（留批次，不落行）
  │
  └─校验通过──> IMPORTED_NOT_PUBLISHED（批次 + 暂存行，模板表零改动）
                      │
              发布（需授权 + 显式模式）
                      │
                      ├─ REPLACE 遇到已有排课且未确认 ──> CONFLICT_REQUIRES_ACK
                      └─> PUBLISHED（模板以 OFFICIAL 写入）
                                │
                            撤销 ──> REVOKED（模板打墓碑，行数不变）
```

状态机是单向的：`REJECTED` / `IMPORTED_NOT_PUBLISHED` / `PUBLISHED` / `REVOKED` 之间没有回退路径。要改课表，重新导入一个新批次，不修改历史批次。

## 3. 关键设计取舍

### 3.1 表头识别只给建议，不给结论

`proposeMapping()` 返回识别到的列、缺失的必需列、未被使用的列。**没有确认的映射就不落库**（`NEEDS_MAPPING`）。不做"按位置猜列"，也不做"按内容猜列名"。

### 3.2 有错就整批拒绝

一行错导致整批不写入。理由不是技术洁癖：如果部分导入，操作人无法判断系统里到底是哪个版本，也就无法判断某节课该不该上。

拒绝时仍然留下 `REJECTED` 批次，记录文件名、哈希、拒绝原因。这样"某人上传过一份错文件"是可追溯的。

### 3.3 上传、发布、撤销是三件事

- **上传**只产生批次与暂存行，模板表指纹不变（有测试断言）
- **发布**才写模板，且必须同时满足：批次状态正确、角色在配置清单内、未残留模拟数据、覆盖模式已确认
- **撤销**不改历史，只让模板失效

### 3.4 幂等靠"差异"而不是"去重"

同一文件上传两次会产生两个批次（审计上应看到两次操作），但第二次发布时差异为 0，`wrote=false`，课次表指纹不变。

这条比"文件哈希去重"更稳：即使文件被重新保存过（哈希变了），只要内容等价，差异仍是 0。

### 3.5 追加与覆盖的差别是"是否承认会替换"

- `APPEND`：只允许新增，遇到同班同时段直接拒绝（这是数据错误，不是版本选择）
- `REPLACE`：会停用本学期现有排课，必须 `acknowledged: true`

D03 未关闭，所以系统不能"聪明地"自行判断该替换还是合并。它只能把后果摆出来，让人确认。

### 4.4 测试抓到的一个真实缺陷

`activeTemplates()` 把 SQL 查出来的 `snake_case` 列直接当作 `camelCase` 对象返回（中间用了 `as` 断言，编译器没报错）。结果是差异比较拿到的 `classId/teacherId/weekday` 全是 `undefined`，**每次发布都认为"现有课表为空"，全量新增**。

后果比看上去严重：幂等断言会假通过（因为根本没有比较），覆盖模式会永远不需要确认。是"重复上传净变化为 0"这条验收把它逼出来的。

修法：显式逐字段映射，不再整对象断言。

## 6. 假设与风险

| 编号 | 内容 | 影响 | 处置 |
|---|---|---|---|
| P3-A1 | 导入格式是"周课表"（星期+节次），不是"日课表" | 若学校只提供逐日课表，需要增加一种布局与日期→星期/单双周换算 | 已在 `docs/04` §8 列为待确认问题 |
| P3-A2 | "发布"= 学校正式生效，因此把模板来源翻为 `OFFICIAL` | 若校方认为还需"核对"环节，`OFFICIAL` 的定义要改 | 若校方否认，改为发布后仍为 `IMPORTED_UNVERIFIED`，另设核对动作 |
| R-16 | XLSX 读取器是自研最小实现，只覆盖 sharedStrings / inlineStr / 数字单元格 | 合并单元格、公式结果、多工作表、日期序列号可能读错 | S01 真实样本核验前不作"支持 Excel"承诺；必要时换用成熟库 |
| R-17 | 只支持 UTF-8 | 学校导出常为 GBK | 已明确报错而非乱码；P7 真实样本阶段补编码探测 |
| R-18 | 一次导入只针对一个学期，不支持跨学期文件 | 若学校一份文件含两个学期需拆分 | 导入前校验学期归属，P7 视真实文件再定 |
| R-19 | 撤销后模板归属仍指向被撤销批次 | 第二个"无差异"批次没有自己的模板，撤销第一个批次会让课表整体失效 | 属预期行为（课表确实来自那一批），但提示文案必须说清楚 |
