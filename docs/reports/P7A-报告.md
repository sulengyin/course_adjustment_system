# P7A 阶段报告：内网界面（受门禁约束）

- 版本：R0 / 2026-11-01
- 数据：全部为虚构样本（`SIMULATED`），未接触任何学校真实资料
- 运行：`npx tsc --noEmit` 通过；`npx vitest run` 26 文件 / 330 项通过；`npm run smoke:ui` 输出 `SMOKE_UI_OK`
- **结论：界面可用，业务门禁不变。P7 本体（真实格式、实机兼容、200 人负载）仍未开工。**

---

## 1. 为什么是 P7A，不是 P7

计划中的 P7 门禁是 `S01 + T-04 + T-08`：真实脱敏课表、多端实机录像、200 人负载。这三项都需要学校资料与设备，当前一项都不具备。

但"打开页面走一遍"是可以在虚构数据上完成的。因此本阶段只做**表现层**：

- 把已实现的能力（只读课表、调课协商、求助登记）做成可点击的页面；
- 把"待校方确认"的能力做成**可见但禁用并说明原因**，而不是隐藏；
- 不新增任何业务规则，不改动任何状态机。

P7 本体保持"门禁后"，编号不动。

## 3. 关键设计

### 3.1 视图必须叠加"已生效变更"（本阶段修复的真实缺陷）

P2 的 `queryByTeacher` / `queryByClass` 只读派生课次表。P4 生效的调课写在 `assignment_state`，只有冲突计算读它。

后果：调课生效、审计里有记录、`activeAssignments()` 里也是新教师，但**教师打开课表仍看到自己**。这是"数据看起来没坏、实际与事实相反"的典型缺陷，且只在有界面的情况下才会被用户第一时间发现。

修复：三个视图共用一个投影（`occurrence LEFT JOIN assignment_state`），并新增 `cancelled` 字段。停课课次仍列出但标记为已停课，不计入"有课"。

### 3.2 理由字段的可见范围

权限矩阵写明"查看他人私人理由"没有任何授权角色。因此：

- 方案详情中 `reason` 只对**发起人**返回；
- 必要确认者、课务管理人员、系统管理员拿到的 `reason` 恒为 `null`；
- 这条规则在服务层执行（`ChangeService.toView`），前端无法通过改请求参数绕过。

确认者仍能看到"哪些课次、从谁转给谁、还要谁确认"——这些是排课事实，本来就对全校可见。

### 3.3 能力表直接来自权限矩阵

页面上的"我的权限"不是另写一份说明，而是遍历 `POLICY` 生成：每个操作给出 `ALLOWED / FORBIDDEN / ROLE_NOT_ASSIGNED`。

管理员打开自己的页面会看到"确认本人课务：无此权限""批准结案：无此权限"——这比文档更能说明"管理员不是超级用户"。

### 3.4 静态资源：白名单而不是路径校验

```ts
const STATIC_FILES = { '/': index.html, '/index.html': …, '/app.js': …, '/styles.css': … };
```

路径不在表里就不进入静态分支，因此不存在"路径穿越""目录列举""符号链接"这类需要逐个防的问题。

响应头固定：`content-security-policy`（禁止内联脚本/样式、禁止外连、禁止被嵌入）、`x-content-type-options: nosniff`、`referrer-policy: no-referrer`、`cache-control: no-store`。

页面里也真的没有内联脚本与内联样式——`tests/ui/page.spec.ts` 会在源码层面检查，不靠 CSP 兜底。

### 3.5 页面只呈现事实，不替学校做决定

- 求助页固定写明"求助 ≠ 已安排 ≠ 已执行"；
- 接单、结案、执行事实等按钮**显示但会失败**，失败原因来自服务端返回码（`ROLE_NOT_ASSIGNED` / `NOT_CONFIGURED`），不是前端写死的文案；
- 课表页把 `unknownDays` / `unresolved` 单独列出，并声明"缺时间不等于没课"；
- 数据来源（模拟/导入未核验/正式）逐条标注。

### 3.6 内网 HTTP 的现实约束

`crypto.randomUUID()` 只在安全上下文（HTTPS 或 localhost）存在。纯内网多为 `http://内网IP`，直接调用会抛错导致无法提交。界面因此保留退路：不可用时生成 `k-<时间>-<随机>` 的幂等键。

这条不是理论问题——`smoke-ui` 在 `127.0.0.1` 之外的环境会直接踩到。

## 5. 本轮发现并修复的问题

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | 课表视图不叠加 `assignment_state` | 调课生效后教师仍看到自己是任课人，界面与审计相反 | 三视图统一投影；新增 `cancelled`；3 项测试 |
| 2 | `publicPrincipal` 不返回 `teacherId` | 页面无法判断"是否有教师档案"，教师入口会被误隐藏 | 补字段（仅返回本人绑定） |
| 3 | 登录页角色选择用 `hidden` 属性，但 `.field { display:flex }` 覆盖了浏览器默认 | 多角色账号看不到选择框 | CSS 增加 `[hidden]{display:none!important}` |
| 4 | 应急后续动作（接单/结案/执行事实）只有服务层方法，没有 HTTP 入口 | P6 报告说"入口阻断"，实际调用得到 404，容易被误读成"还没写" | 补齐 9 条路由，统一返回显式拒绝码并留审计 |
| 5 | 路径段 `decodeURIComponent` 失败抛错 | 畸形 URL 变成 500，被误判为服务端故障 | 统一 `decodeSegment`，失败返回 400 |
| 6 | 页面内联 `style="margin-top:…"` | 被自身 CSP 拦截，样式静默失效 | 改为 `.mt8/.mt10` 工具类 |
| 7 | 初始口令生成有约 3% 概率产出“全字母”口令 | 首次部署偶发被强度校验拒绝，表现为“环境问题” | 改为按构造保证字母+数字各一，补 500 次生成测试 |
| 8 | 前端把所有 401 都当作"会话失效" | 登录/改密接口的 401 其实分别是"账号或口令不对""原口令不对"，按失效处理会清空已填内容、弹回登录页并提示"登录已失效"，把用户引向会话与网络方向 | 只有响应 `code === 'UNAUTHENTICATED'` 才按会话失效处理；其余交回表单按 `code` 提示 |
| 9 | 改密表单不看响应状态码，失败也当成功 | 口令强度不足时服务端返回 400，前端仍提示"口令已修改，请用新口令重新登录"；用户拿着**根本没生效**的新口令登录 → 401 → 又被第 8 条放大成"登录已失效"。改密静默失败，是最严重的一条 | 改密后必须判 `res.ok`，失败按 `code`/`message` 在原页说明（并写清长度≥12、含两类字符、不能与旧口令相同）；新增 3 项渲染测试 |

第 4 条是"文档说已阻断、代码其实没有入口"的偏差，属于追溯表与实现不一致，已在本轮补齐。

第 8、9 条是**交付后由用户实际体验发现**的，两条叠在一起才构成完整故障链：

1. 用户首登改密，新口令不满足强度要求（≥12 位且含字母/数字/符号中的两类），服务端 400 拒绝；
2. 前端不看状态码，一律提示"口令已修改"，用户认为已成功；
3. 用户用新口令登录 → 401；
4. 前端把 401 一律当成会话失效 → "登录已失效"。

服务端自始至终是对的（`changePassword` 在事务里更新口令、吊销全部会话、留审计）。**错的是界面把"失败"说成"成功"、把"口令不对"说成"会话过期"**——两次都改变了用户接收到的因果，用户据此做出的判断必然偏离。

这类缺陷单元测试挡不住：两侧单独看都正确，只有把"首登改密 → 回登录页 → 用新口令登录"连起来才会暴露。已补的 5 项渲染测试都做过回退验证（去掉修复必红）。

另外，冒烟脚本第一次跑时用"刚被改派的课次"发起求助，被服务端以 `FORBIDDEN` 拒绝——这是**规则正确**（求助只能针对本人当前承担的课次），脚本改为另选课次。

## 7. 明确没做

- 导入界面（上传/映射/预览/发布）：导入管线已有服务层与脚本，但发布岗位 `TBD_BLOCKED`，做界面只会造出一个"点了也没用"的按钮。

- 账号管理界面：属 `MANAGE_ACCOUNTS`，首版用 `scripts/init-admin.ts` 足够；界面上线前需要单独的权限评审。
- 通知渠道：`notification.channels` 未配置，页面只显示站内事实，不发任何消息。
- 无障碍与键盘导航：未验证，列在风险中。

## 9. 结论与下一步

- 界面在虚构数据上可完整走通"看课表 → 发起调课 → 双方确认 → 生效 → 课表更新 → 求助 → 被阻断的后续动作"。
- 业务门禁一项未动：所有 `TBD_BLOCKED` 仍然拒绝，页面只是把它显示出来。
- **P7 本体仍为门禁后**；下一步需要学校提供脱敏真实课表（S01）、可用设备（T-04）与并发目标（T-08）。
- 在拿到真实数据前，不建议把本界面部署给真实教师使用——不是因为功能不完整，而是因为模拟数据不能替代学校正式发布的课表。
