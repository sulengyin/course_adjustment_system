## 2. 本阶段做与不做

### 2.1 唯一开放的用户操作：求助

教师可以为**本人当前承担的课次**发起求助。系统只记录：

- 谁、针对哪个课次、什么时候、说了什么（说明文本）
- 状态 `REQUESTED`
- 授课核验 `PENDING`

不产生：通知送达、协调负责人、结案、授课已核验。

### 2.2 所有依赖未决规则的操作一律阻断

| 操作 | 返回码 | 阻断项 | 说明 |
|---|---|---|---|
| 标记已通知 | `NOT_CONFIGURED` | BIZ-13 | 送达语义未定，不显示"已送达" |
| 登记口头接受 | `ROLE_NOT_ASSIGNED` | D06/D07 | 记录者任职名单未定，任何角色都不能登记 |
| 接单成为协调者 | 教师 `FORBIDDEN`；C/R `NOT_CONFIGURED` | E5/D07/O2-1 | 候选范围与"有效接单"定义未定 |
| 移交协调责任 | `NOT_CONFIGURED` | D07 | 接手判定未定 |
| 提交结案 | `NO_COORDINATION_OWNER` | — | 无法产生负责人，因此无从提交 |
| 批准结案 | `ROLE_NOT_ASSIGNED` | BIZ-05 | 结案确认人未指定 |
| 录入执行事实 | `ROLE_NOT_ASSIGNED` | BIZ-03 | 何时算已执行未定 |
| 补确认逾期 | `NOT_CONFIGURED` | BIZ-04/TIME | 不返回 17:00、24:00 等任何推算 |
| 主责拒绝后升级 | `NOT_CONFIGURED` | E5 | 要求升级是确定的，升级给谁是未定的 |

阻断不是静默失败：每次尝试写一条 `EMERGENCY_ACTION_DENIED` 审计（只含操作名与错误码，不含说明文本）。

## 3. 五件事的分离（本阶段核心）

```
求助 ──✗──> 已通知 ──✗──> 有人承接 ──✗──> 已结案 ──✗──> 已上课/已核验
```

| 断言 | 实现方式 | 测试 |
|---|---|---|
| 求助 ≠ 已通知 | 响应中 `notified` 恒为 `false`，无"标记已通知"写入口 | 服务「送达判定未定」 |
| 求助 ≠ 有人承接 | 请求表初始 `owner_teacher_id = NULL` | 服务「状态 REQUESTED，无负责人」 |
| 有负责人 ≠ 已结案 | 负责人与结案是两个字段/状态 | 领域「有了负责人不等于结案」 |
| 结案 ≠ 已核验 | `teaching_verification` 独立于 `status`；`closeCase` 只改自己那条线 | 领域「结案完成但未核验」 |
| 代录 ≠ 本人确认 | `proxyRecord` 恒返回"待本人确认、不计入确认" | 领域「代录只产生待本人确认」 |
| 口头 ≠ 有效接单 | 口头只置 `provisional_teacher_id`，`owner` 仍为空 | 领域「口头登记后 owner 仍为空」 |

`TEACHING_PENDING` 不是 `status` 的取值，而是"结案后仍未核验"时附加显示的状态（`displayStates` 同时返回 `CLOSED` 与 `TEACHING_PENDING`）。

## 4. 关键设计取舍

### 4.1 不因为"有 C 角色"就放行接单

权限矩阵规定接单由 C/R 承担，但 C 是**动态角色**，只能由"先有效接单"产生；而接单的候选范围（责任组/当日主责/代理/兜底）未定（E5）。若让任意教师接单，等于替学校决定"谁有资格接单"。

因此当前没有任何人能接单。这不是缺陷，是"规则未配置"的显式表现。

### 4.2 口头与在线冲突不按时间排序

V23-10 已确认：12:51 口头（12:54 补录）与 12:52 在线接单同时存在时，不得按"谁更早"裁定。领域函数保留双方来源并置 `AMBIGUOUS`，`owner` 为空；后到的接单也不会自动消除歧义。

### 4.3 结案字段按 V2.3 校验，不自行增加必填项

只校验 V2.3-02 R02-B4-7 明列的 5 项：结果、经过、责任人、时间、联系记录。缺项返回 `CLOSURE_FIELDS_MISSING` 并逐项列出，不写入。

### 4.4 求助说明不进入审计链

说明可能含家庭、健康等私人情况。审计只写 `status/occurrenceId/ownerTeacherId/teachingVerification`，`note` 留在业务表；测试用"临时无法到校"样本断言审计表零命中。

## 7. 本轮边界审查发现并修复

| # | 问题 | 原行为 | 现行为 |
|---|---|---|---|
| 1 | `TimetableService.recordEmergencyNote` 接受裸 `recordedBy` 且无权限 | 任何调用方可冒充记录者写备注 | 删除该入口；备注写入只保留存储层，用户操作走权限校验后的服务 |
| 2 | 权限矩阵漏列"求助" | 按"默认拒绝"将无法求助 | 补录两行，来源 V2.3-01 §5.1；策略表同步 |
| 3 | 被拒绝的接单尝试无痕迹 | 无法发现"有人试图使用未定流程" | 所有阻断操作写 `EMERGENCY_ACTION_DENIED`（不含说明文本） |
| 4 | 备份对账不含求助记录 | 截断求助表后重签 sha 无法发现 | 对账新增 `emergencyRequests`；清单格式升为 v2 |
| 5 | 空/超长说明 | 可能写入空白或超长文本 | 服务层限制 1–2000 字符，违反返回 `BAD_INPUT` |
