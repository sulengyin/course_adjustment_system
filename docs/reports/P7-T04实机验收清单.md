## 1. 本清单要回答的问题

界面的静态约束测试只能证明"代码里该有的都有"，证明不了"老师在真实设备上点得动"。
本清单只做一件事：在真实设备与真实浏览器上，把一位教师一天里会做的事走一遍，逐条留证。

- 判定只有三种：`PASS` / `FAIL` / `BLOCKED`（缺设备或缺账号）。**不允许写"基本可用"**。
- `FAIL` 必须附：设备、浏览器版本、操作步骤、截图、以及是否可复现。
- 未测的项记 `NOT_RUN`，不得因为"其他地方过了"而推定为通过。

## 5. 用例步骤与判定

### M1 登录与首登强制改密

1. 打开首页，输入登录名与初始口令。
2. 首登账号应被拦到改密页；改密成功后直接进课表，不要求二次登录。
3. 用旧口令再登一次，应失败。

判定：改密后旧口令失效且新口令可进；页面不出现任何明文口令回显。

### M2 本周课表与今日列

1. 进"我的课表"，默认展示本周。
2. 核对节次时间、班级、科目与 `docs/12` 的教师表一致（抽 3 条）。
3. 今日列有高亮；周末打开时不应有高亮列。

判定：科目/班级/节次无错位；今日列位置与服务端日期一致（不随电脑时钟漂移）。

### M3 切周与学期切换

1. 上一周 / 下一周来回切换 3 次。
2. 若有多个学期，切换学期后周次与日期同步变化。

判定：切周后数据不串周、不残留上一周的行。

### M4 候选名单滚动与过滤（回归项）

1. 在课表点任意一节自己上的课 → "发起调课"。
2. 点开"调课给"，名单出现在页面内（不是系统下拉浮层）。
3. **拖动滚动条到底部，再点滚动条本身**——名单必须仍在，页面不得回退或消失。
4. 输入姓名片段过滤，名单实时收窄；清空后恢复。
5. 分组标题应显示"本学期任教这个班 / 同年级 / 跨年级"之类理由，且顺序为该档位在前。

判定：以上 5 步全部成立。第 3 步是历史缺陷（原生下拉弹层点滚动条整层关闭），必须逐设备确认。

### M5 发起调课并提交

1. 选一位候选，填写原因，提交。
2. 提交后应显示"等待确认"，并列出必要确认者（原教师与新教师）。
3. 未选人时提交按钮不可用；候选未就绪时提交也被拦住。

判定：确认者名单不得缺人；缺人即为 `FAIL`（这是业务不变量，不是体验问题）。

### M6 对方收到并确认

1. 用第二个账号登录，进"待我确认"，能看到该方案。
2. 确认后，发起方看到状态变为生效。

判定：确认前后状态文字准确，不得出现"已确认"却仍待确认的情况。

### M7 生效后课表叠加

1. 回到课表，目标课次应显示新教师。
2. 详情里能看到变更记录与该课次的原教师。

判定：课表叠加生效变更，且原记录可追。

### M8 拒绝与撤回

1. 对方拒绝，方案状态为已拒绝，课表不变。
2. 发起方在对方确认前撤回，方案状态为已撤回。

判定：拒绝与撤回都不得改动课表。

### M9 设置页偏好保存

1. 顶栏"设置" → 修改"排除该节次有课"等开关 → 保存。
2. 回到调课页重新取候选，名单应按新偏好变化（被排除者连同原因列出，不静默消失）。

判定：保存后立即生效；无教师档案的身份不显示"我的偏好"入口。

### M10 权限自检

1. 教师身份进"权限自检"，确认导入、发布、账号管理等为不允许。
2. 页面不应出现这些入口的可点击版本。

判定：不可用项要么不显示，要么明确灰化并说明原因。

### M11 窄屏布局

1. 手机竖屏打开首页与课表。
2. 顶栏不重叠、页签整行、键值对单列；课表可横向查看且不撑破屏幕。

判定：无横向滚动条溢出、无元素被裁切。

### M12 断网与超时

1. 打开飞行模式后点"确认"或"提交"。
2. 应给出明确失败提示，且不把操作标成成功。

判定：失败必须可见；恢复网络后可重试，且不产生重复记录（幂等）。

### M13 键盘与焦点

1. 只用 Tab / Shift+Tab / Enter / Esc 走完登录 → 课表 → 打开名单 → 选人 → 提交。
2. 每一步焦点环可见，Esc 能关闭名单且焦点回到触发按钮。

判定：全程不离开键盘；焦点不丢失在页面外。

### M14 候选不可用态

1. 在候选请求会失败的条件下（演示实例可临时停后端，或断开网络）打开"调课给"。
2. 应显示"候选不可用"的原因与重试入口，**不得列出任何教师姓名**，提交按钮不可用。
3. 恢复后点重试，名单正常出现。

判定：出现全校名单即 `FAIL`（P7I-13 不变量）。
