# 已确认决策清单｜以用户最后一次明确表态为准

**作用：** 新开发者核对需求“哪些已经拍板”。日期均为当前项目在2026-10-27前后的连续讨论记录；本整理不形成新决策。

| ID | 已确认规则 | 不应误解为 |
|---|---|---|
| 平台 | 鸿蒙电脑/Windows/macOS电脑和鸿蒙/Android/iOS手机使用统一Web应用 | 各平台都要本机运行Python后端 |
| 部署 | 第一版仅校园内网络；软件与服务端部署地址解耦；学校能提供持续运行电脑 | 第一版必须提供校外访问或学校主机配置已经验收 |
| 账号 | 学校统一开通并关联稳定教师ID | 开放自行注册或以姓名作为身份 |
| 可见性 | 普通教师可查看其他教师正常课表与已确认客观任务 | 所有私下调课理由、联系人和敏感信息对全体可见 |
| 日常调课 | 不默认需教务处逐项审批；相关教师本人确认与冲突复核后正式生效 | 管理员可代为同意 |
| R01 | 必要确认者仅为授课责任或任务责任**实际被改变的教师**；班主任无需额外确认，生效后通知 | 固定两人确认或班主任审批 |
| R02 | 生效前申请可撤回；生效后取消必须新建恢复/调整方案并重新确认；管理员仅能免确认修正不改变授课/任务责任的资料错误 | 直接删掉已生效调整 |
| R02-A | 已执行授课事实保留；恢复仅对未执行课次；执行事实错误走独立纠错 | 用改课表覆盖历史实际授课人 |
| R02-B1 | 授权人员可登记临时应急安排，但不同于正式生效、教师接受或实际执行 | 临时登记就是有效授课指派 |
| R02-B2 | 普通教师可发紧急求助，学校授权人员登记临时应急安排 | 求助者可替别人确认 |
| R02-B3 | 口头/当面代课接受可登记，教师事后本人补确认，实际执行另记 | 登记者代表教师完成电子确认 |
| R02-B3-1 | 应于下一工作日结束前补确认，逾期进入待核验，不自动同意/拒绝 | 时间点已定为17:00或24:00 |
| R02-B4 | 根据距离上课时间动态升级并由授权人员人工处置 | 具体提前分钟数已确定 |
| R02-B4-1 | 学校指定应急责任组和当日主责；代理按当日有效排班确定 | 固定某老师永远当代理 |
| R02-B4-3 | 先通知主责，未接单时按紧迫程度升级代理，紧迫时可立即升级 | 固定3/5/10分钟已审批 |
| R02-B4-2 | 应急协调结案与授课事实核验分开，未落实继续待处置 | 结案=课程已完成 |
| R02-B4-5 | 学校预设可随排班变化的最终兜底责任岗位 | 实际岗位名称/人员已指定 |
| R02-B4-6 | 主责或代理提交结案，由学校指定授权人员最终确认 | 最终兜底人员自动有结案审批权 |
| R02-B4-7 | 结案记录结果、经过、责任人、时间与必要联系记录；未核验仍待核验 | 证据具体表单格式已敲定 |
| O1 | 授权人员可登记口头协调接单、临时视为有人协调；本人事后追认，区分时间及来源 | 口头已登记就是本人电子追认 |
| O2 | 先**有效**接单者为当前唯一协调负责人；他人协助；移交须明确留痕 | 口头/在线互相冲突的先后裁定已确定 |
| O3 | 主责明确拒绝或无法处理时，立即升级到当天排班代理并留痕 | 未读或电话未接通也自动当作拒绝 |

**状态补充：** 用户在最新一轮明确提出“暂时先不决策”，因此 **O2-1（口头与在线接单冲突裁定）** 与 **O4-1（联系失败如何分类和处置）** 不得以此前推荐选项替代。具体升级分钟阈值保持未决。
