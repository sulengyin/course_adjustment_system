# 校内课务协同系统

面向中学教务的**调课协同**系统：把一个"换课"的请求，变成一条有依据、有确认、可追溯的业务记录。

一句话说清边界：系统**执行**学校已经定下的规则，不**替学校决定**规则。
标着"待校方确认"的事项，在拿到书面依据前一律不可用。

## 三条不可让步的原则

1. **不代替学校决策。** 制度未定的权限记为 `TBD_BLOCKED`，界面会明确说"未开放"，而不是先给个默认值用着。
2. **真实数据不进仓库。** 仓库里只有代码、测试与虚构夹具；真实库、名单、备份都在仓库外（见 [数据与隐私](#数据与隐私)）。
3. **每一次变更都留痕。** 谁发起、谁确认、依据是什么、卡在哪一步，都在审计里，不靠聊天记录回忆。

## 这是什么（业务侧）

"调课"是**授课责任变更**的总称，包含四类动作：代课、对调、调整时间、停课。
共同点是——**受影响教师必须本人逐人确认**，不能由发起人代确认；缺一个人的确认就不生效。

两种身份要分清：

- **代发起**：有相应能力的人（如教务）替某位老师提交申请。`submitted_by` 记被代教师，`created_by` 记实际代办人。
- **代确认**：不存在。被代教师仍在自己名下看到待确认，本人不点就不生效。

## 快速开始

要求 Node.js **22.5+**（使用内置 `node:sqlite`；CI 与开发机均为 24）。

```bash
npm install
npm test          # 全量测试：契约规格 + 领域 + 服务 + HTTP + 界面渲染
npm run typecheck # tsc --noEmit

# 真实进程 + 真实 HTTP，自建临时库、自选端口、结束即删
npm run smoke:ui      # 登录→改密→课表→发起调课→双方确认→生效→求助→审计链
npm run smoke:deploy  # 环境变量入口 + 备份恢复演练

# 多视口浏览器测试（首次需装 Chromium）
npx playwright install chromium
npm run test:e2e      # 320/375/412/430/1280 五个视口
```

三层测试的分工，以及**它们各自测不到什么**，写在 `docs/14 §8`。一句话：
`test:e2e` 是 Chromium 的视口模拟，不是真机，iOS Safari 与微信/钉钉 WebView 的差异仍要实机验收。

### 起一个演示实例

演示库只写虚构数据，且拒绝覆盖已有数据。它**不常驻**——库可随时用 `seed:demo` 重建，
没必要每天占一个端口和一份日志；需要时再拉起来：

```bash
export CA_DB_PATH="$HOME/ca-demo.sqlite"      # 放在仓库外
npm run seed:demo                              # 生成虚构校历与演示账号

CA_BIND_ADDRESS=192.168.x.x CA_PORT=18088 CA_DB_PATH="$CA_DB_PATH" npm run serve
```

`seed:demo` 会打印一个**随机**初始口令，演示账号共用它，只出现这一次；登录后必须先改成自己的口令。
仓库里没有可用的默认口令，拿不到这次输出就进不去。

已经按 `serve:auto` 部署过时，更省事的做法是 `CA_WITH_DEMO=1 npm run serve:auto`，
用完 `npm run serve:auto -- --stop-demo` 只停演示，正式实例不受影响。

三个环境变量都是必填，**程序不猜默认值**——缺一项就报错退出。这样部署时不会悄悄绑到错误的地址上。

### 首次部署到真实环境

```bash
CA_DB_PATH=<库文件路径> CA_ADMIN_LOGIN=admin CA_ADMIN_NAME=教务管理员 npm run init-admin
```

初始口令只在终端打印这一次，不落盘、不入日志，首登强制改密。

## 目录

| 目录 | 放什么 |
|---|---|
| `src/` | 实现。`domain/` 纯规则、`service/` 业务编排、`store/` SQLite、`auth/` 认证与权限、`server/` HTTP |
| `spec/` | **可执行规格**：反例与必测场景，以及一个独立参考实现 |
| `tests/` | 实现侧的测试（领域、服务、HTTP、界面渲染、存储） |
| `web/` | 前端。纯静态、无构建、无 CDN 依赖，直接在浏览器里跑 |
| `scripts/` | 运维与导入脚本（见下） |
| `docs/` | 决策、依据、验收记录。**规则的出处在这里，代码只是它的实现** |

### `spec/` 和 `src/` 不是两套实现

`spec/` 是**规格**：把需求方的条款写成可执行的场景，并配一个刻意写得朴素、只求正确的参考实现。
`src/` 是**产品实现**，要在性能、审计、权限上做得更多。

两者并存是为了回答一个问题：需求变了，是规格错了，还是实现跑偏了？
改 `src/` 时 `spec/` 必须保持通过；改规则时先改 `spec/`，再改 `src/`。

`spec/` 里全部是虚构数据（示例教师甲、`13800138000` 这类），不允许从正式库复制。

## 运维

| 命令 | 用途 |
|---|---|
| `npm run serve:auto` | 读当前网卡地址，保证正式实例在跑；`CA_WITH_DEMO=1` 时连演示实例一起管，`-- --stop-demo` 只停演示 |
| `npm run backup` / `restore` | 库的备份与恢复 |
| `npm run reset-password` | 管理员重置他人口令 |
| `npm run grant-role` | 授予角色（如系统管理员 `A`） |
| `npm run grant-capability` | 授予**单项能力**（如"代他人发起调课"），必须写明依据 |
| `npm run import-base` / `import-bell` / `import-teachers` / `import-timetable` | 各类真实数据导入，导入前先在预览里核对 |

`serve:auto`、`backup`、`restore` 都会读写真实库，操作前先确认 `CA_DB_PATH` 指向哪里。

## 数据与隐私

- 真实库（`*.sqlite`）、导入的原始表格、备份、运行日志**都不在仓库里**，`.gitignore` 已覆盖。
- 文档中出现的 `192.168.x.x`、`<DB_PATH>` 一律是占位符，实际值由部署时打印，不写入仓库。
- 测试与演示数据必须是虚构的；从正式库复制数据到测试里，视为事故。
- 本仓库公开。发现误提交凭据时：**先轮换口令，再处理历史**，顺序不能反。
